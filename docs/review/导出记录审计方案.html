一、需求目标

  • 记录所有客户的每一次导出行为，包括前端页面导出和群内命令（发送台账）触发的导出
  • 记录当时的完整导出参数：筛选条件、时间范围、导出类型、字段模板、操作人、所属企业等
  • 每次导出的数据条数要显著记录并在列表中提醒展示
  • 导出产物（Excel 文件）同步上传 COS 指定审计目录，随时可回看当时导出的真实数据
  • 本功能为内部复查功能，仅超级管理员（super_admin）可见，客户侧无任何感知

三、方案架构

核心思路：一个统一的审计封装 + 各入口一行埋点。不改变任何现有接口签名和响应行为，审计动作全部在导出成功后追加执行，失败静默降级。

5 个导出入口
导出成功后
→
export_audit.record_export()
统一审计封装（新模块）
→
写入 export_records 表
参数 JSON + 条数（毫秒级，立即返回）
→
后台上传队列
副本传 COS export_audit/ 后回写记录

超管前端「导出记录」页签
←
GET /api/insurance/export-records（@admin_required）

新增模块：insurance/export_audit.py

对外只暴露一个函数，5 个入口统一调用：

def record_export(db, cos, *,
                  user_id, user_name, enterprise_id, enterprise_name,
                  export_type,          # ledger_excel / enterprise_report / batch_zip / ledger_cmd / renewal
                  trigger_way,          # web / cmd
                  params: dict,         # 当时的完整导出参数（原样 JSON 存储）
                  row_count: int,       # 本次导出数据条数
                  filename: str,
                  file_bytes: bytes = None,   # 传入则上传审计副本
                  cos_url: str = "",          # 已有 COS 地址（群命令场景）直接复用
                  status="success", error_message=""):
    """记录一次导出行为。内部整体 try/except，任何异常只打日志，绝不影响导出主流程。

    副本上传在后台线程执行：主流程只做一次轻量写库（copy_status=pending）后立即返回，
    file_bytes 交给单线程 ThreadPoolExecutor 队列异步上传 COS，
    上传完成后回写 cos_key / cos_url / copy_status=done（失败则 copy_status=failed）。
    客户的导出响应耗时与审计前完全一致。"""

四、数据库设计（export_records 表）

沿用现有幂等建表模式：在 insurance/db.py 新增 init_export_records_table(db)，在 main.py 的 init_insurance_tables(db) 附近调用，首次启动自动建表。

CREATE TABLE IF NOT EXISTS export_records (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    user_id         INT NOT NULL COMMENT '操作人 users.id（群命令为绑定账号）',
    user_name       VARCHAR(64)  DEFAULT '' COMMENT '操作人姓名（冗余，防账号删除后无法追溯）',
    enterprise_id   INT          DEFAULT NULL COMMENT '导出数据所属企业',
    enterprise_name VARCHAR(128) DEFAULT '' COMMENT '企业名称（冗余）',
    export_type     VARCHAR(32)  NOT NULL COMMENT 'ledger_excel/enterprise_report/batch_zip/ledger_cmd/renewal',
    trigger_way     VARCHAR(16)  NOT NULL DEFAULT 'web' COMMENT 'web=页面 / cmd=群命令',
    params          TEXT COMMENT '导出时的完整参数 JSON（筛选条件/时间范围/字段模板等）',
    row_count       INT          DEFAULT 0 COMMENT '本次导出数据条数',
    filename        VARCHAR(256) DEFAULT '' COMMENT '导出文件名',
    file_size       INT          DEFAULT 0 COMMENT '文件大小（字节）',
    cos_key         VARCHAR(512) DEFAULT '' COMMENT '审计副本 COS 路径',
    cos_url         TEXT COMMENT '审计副本访问地址',
    status          VARCHAR(16)  DEFAULT 'success' COMMENT 'success / failed',
    copy_status     VARCHAR(16)  DEFAULT 'pending' COMMENT '副本上传状态 pending/done/failed/none（none=ZIP等无副本类型）',
    error_message   TEXT COMMENT '失败原因',
    roomid          VARCHAR(128) DEFAULT '' COMMENT '群命令场景：触发群ID',
    trigger_text    VARCHAR(128) DEFAULT '' COMMENT '群命令场景：原始命令文本，如"发送台账本月"',
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '导出时间',
    INDEX idx_enterprise (enterprise_id),
    INDEX idx_type (export_type),
    INDEX idx_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='导出行为审计记录（内部功能）';
✅ 冗余字段说明
user_name / enterprise_name 做冗余存储，保证账号或企业被删除后审计记录仍完整可读；params 原样存 JSON，前端弹窗展示完整参数，无需关联其他表。

五、各入口埋点方案

入口埋点位置记录的 paramsrow_count 来源副本处理
1. 台账 Excel export_excel() 生成 Excel bytes 后、send_file 前 export_type / date_start / date_end / export_label / merge_by_plate / field_names / enterprise_id / 前端传入的筛选摘要 len(invoices) Excel bytes 上传审计副本
2. 企业经营报告 export_enterprise_report() 生成后 enterprise_id / enterprise_name / date_start / date_end / format 报告覆盖的记录条数 Excel bytes 上传审计副本
3. 批量下载原文 ZIP 异步任务打包完成时 record_ids 列表 + 数量 len(record_ids) 不上传副本（原文 PDF 本就在 COS，存 record_ids 即可完整回溯，避免 ZIP 占用双倍存储）
4. 群命令台账 core/fetcher.py 上传 COS、群发消息成功后 trigger_text（原始命令）/ label / date_start / date_end / sender / roomid / 绑定账号 现有流程已统计的 count 复用已有 COS 文件（ledger_exports/ 已是持久副本，直接记 cos_key，不重复上传）
5. 续保任务导出 renewal_api.export() 生成后 status / date_start / date_end / keyword / assignee 导出行数 Excel bytes 上传审计副本

另外建议：导出失败也记一条（status=failed + error_message），失败行为同样有复查价值（如群命令因权限被拒、参数解析失败等）。

六、导出文件副本 · COS 存储规则

审计副本统一存放在独立目录，按月 + 企业分层，方便按客户回看和后续生命周期管理：

{prefix}export_audit/{YYYYMM}/{enterprise_id}/{unix_timestamp}_{export_type}_{user_id}.xlsx

示例：wxbot/media/export_audit/202607/12/1752830000_ledger_excel_35.xlsx
  • 使用现有 CosStorage.upload_bytes(data, cos_key_suffix, download_filename)，无需扩展 COS 封装
  • 上传在后台线程执行：模块内维护一个单线程 ThreadPoolExecutor 上传队列（与保单识别 Queue 串行消费同思路，控制内存与并发），客户主流程零等待；上传完成后回写记录的 copy_status
  • download_filename 传原始中文文件名，回看下载时文件名与客户当时下载的一致（Content-Disposition）
  • 群命令台账已上传的 ledger_exports/ 文件不搬移、不复制，审计记录直接引用其 cos_key
  • 保留策略：默认永久保留（审计属性），如后续存储成本敏感可在 COS 控制台对 export_audit/ 前缀配置生命周期规则（如 2 年转低频/归档），不在代码中做自动删除

十、兼容性与降级策略

  • 不改任何现有接口签名与响应结构：埋点全部是导出流程内部追加调用，历史前端版本、群命令流程完全不受影响
  • 审计绝不阻断导出：record_export() 内部整体 try/except；写库失败 → 仅打日志；副本上传失败 → 记录保留（copy_status=failed + error_message），前端「下载副本」按钮置灰并提示
  • 副本上传后台异步，客户主流程零影响：主流程只做一次轻量 INSERT（毫秒级）即返回，Excel bytes 交给后台单线程上传队列处理；服务重启时队列中未完成的上传会丢失，对应记录停留在 copy_status=pending，可在前端识别并提示（参数和条数仍完整可查，仅副本缺失）
  • 建表幂等：CREATE TABLE IF NOT EXISTS，老库升级无感知，无需手工 SQL
