# 销售看板方案（待确认）

> 状态：方案评审中，未开发
> 日期：2026-07-18
> 原型：同目录 `销售看板原型.html`

## 一、需求说明

基于保单台账数据（insurance_records）为每个企业生成销售看板：

- **仅企业管理员可查看**（role = enterprise；超管可切换企业查看；员工 employee 无权限）
- **按模板配置**：超管预设系统默认模板，企业管理员可在模板基础上微调自己企业的看板
- **支持自定义**：
  - 自定义统计指标：指标卡绑定台账字段做求和/计数/平均
  - 自定义筛选条件：如「车险保费 = 保费求和，条件：险种 包含 车险」
  - 自定义分组维度：图表/排行可按保司、险种、业务员、月份等分组
  - 展示列可选：排行表展示哪些列可配置
- 典型指标：总保费、总佣金、员工提成、保单量、按保司/险种拆分
- **业绩目标管理**：
  - 企业整体目标 / 条件目标（如某保司、某险种的保费目标）
  - 员工业绩目标：按「目标项」组织，每个目标项可带筛选条件（如车险保费目标 = 保费求和，条件：险种包含车险）；目标项内支持「全员统一」一键设置，也支持按人单独设置（单独设置优先于统一值）；可同时存在多个员工目标项（如总保费目标 + 车险保费目标）
  - 目标周期：当月 / 当季度 / 今年（滚动周期，自动按当前周期计完成率），或自定义起止日期
  - 看板展示目标完成率：指标卡进度条、目标完成区块、业务员排行表中的每人完成率
- **数据说明（?）**：看板上每个数据（指标卡、目标、图表、排行列）旁带「?」图标，悬停展示**数据来源和计算公式**，如：统计字段、筛选条件、时间范围、聚合方式；公式字段（如提成）额外展示其费率公式来源（如 提成 = 佣金 × 50%）

## 二、方案选型

| 方案 | 说明 | 结论 |
|------|------|------|
| **A. 配置驱动 + 后端内存聚合（推荐）** | 看板配置存 JSON，后端查询企业时间范围内的记录，应用现有公式引擎后在 Python 内存聚合 | ✅ 采用。display_fields 为 JSON 字段且公式在应用层计算，无法下推 SQL；单企业数据量（数千条/年）内存聚合毫秒级 |
| B. SQL 生成式聚合 | 按配置拼 SQL（JSON_EXTRACT 聚合） | ❌ 公式字段（如提成）在应用层算，SQL 拿不到；金额是文本格式需清洗 |
| C. 复用导出 Excel 由客户自己透视 | 不做页面 | ❌ 不满足"看板"需求 |

关键复用：

- **提成/佣金等计算字段**：直接读取现有 `fee_formula` 公式引擎应用后的字段值（`apply_user_config_to_fields` 产出），看板不重复实现计算
- **权限体系**：复用现有 JWT + role（super_admin / enterprise / employee）
- **模板 scope 模式**：参照 `user_field_config` 的 global / enterprise 分层

## 三、数据库变更

新增一张表（首次启动自动建表，与现有风格一致）：

```sql
CREATE TABLE IF NOT EXISTS dashboard_config (
    id INT AUTO_INCREMENT PRIMARY KEY,
    scope VARCHAR(16) NOT NULL COMMENT 'global=系统默认模板 / enterprise=企业自定义',
    scope_id INT DEFAULT NULL COMMENT 'enterprise 时为企业ID',
    config_json LONGTEXT COMMENT '看板配置JSON',
    enabled TINYINT DEFAULT 1 COMMENT '是否启用看板（超管可按企业开关）',
    updated_by INT DEFAULT NULL COMMENT '最后修改人user_id',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_scope (scope, scope_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='销售看板配置';
```

配置解析顺序：`enterprise(本企业) → global(系统默认)`，企业未自定义时用系统默认模板。

目标表（新增）：

```sql
CREATE TABLE IF NOT EXISTS dashboard_targets (
    id INT AUTO_INCREMENT PRIMARY KEY,
    enterprise_id INT NOT NULL COMMENT '所属企业',
    target_type VARCHAR(16) NOT NULL COMMENT 'enterprise=企业整体 / condition=条件目标 / employee=员工目标',
    name VARCHAR(64) NOT NULL COMMENT '目标名称，如 月度总保费目标',
    metric_agg VARCHAR(8) DEFAULT 'sum' COMMENT '聚合方式 sum/count',
    metric_field VARCHAR(64) DEFAULT '保费' COMMENT '统计字段',
    filters_json TEXT COMMENT '筛选条件JSON，条件目标用（如保司=平安）',
    employee_name VARCHAR(64) DEFAULT NULL COMMENT '员工目标：业务员姓名；NULL 表示该目标项的全员统一值',
    period_type VARCHAR(16) NOT NULL COMMENT 'month=当月 / quarter=当季 / year=今年 / custom=自定义',
    period_start DATE DEFAULT NULL COMMENT 'custom 起始',
    period_end DATE DEFAULT NULL COMMENT 'custom 截止',
    target_value DECIMAL(14,2) NOT NULL COMMENT '目标值',
    enabled TINYINT DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_ent (enterprise_id, target_type),
    UNIQUE KEY uk_target (enterprise_id, target_type, name, employee_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='销售看板业绩目标';
```

目标规则：

- `month / quarter / year` 为**滚动周期**：完成率始终按「当前自然月/季/年」的实际数据计算，无需每期重设
- `custom` 为固定起止日期的一次性目标（如开门红活动）
- 员工目标按**目标项**组织：`(enterprise_id, target_type='employee', name)` 相同的记录为同一目标项，共享该目标项的统计口径（metric_agg / metric_field）、筛选条件（filters_json）、周期（period_type）；即员工目标同样支持条件目标（如「车险保费目标」条件：险种 包含 车险）
- 员工目标解析：**个人单独设置 > 全员统一值**（同一目标项内 employee_name 为 NULL 的记录作为全员默认，employee_name 有值的记录按人覆盖）；业务员名单来源于台账「业务员」字段的去重值
- 唯一约束：`UNIQUE(enterprise_id, target_type, name, employee_name)`
- 排行表可将每个员工目标项作为「目标值 + 完成率」列展示，展示哪些目标项在看板配置的排行配置中勾选
- 完成率 = 周期内按目标条件聚合的实际值 ÷ 目标值

### config_json 结构

```json
{
  "time_field": "签单日期",
  "cards": [
    {"id": "c1", "title": "总保费",   "agg": "sum",   "field": "保费"},
    {"id": "c2", "title": "总佣金",   "agg": "sum",   "field": "佣金"},
    {"id": "c3", "title": "员工提成", "agg": "sum",   "field": "员工提成"},
    {"id": "c4", "title": "保单量",   "agg": "count"},
    {"id": "c5", "title": "车险保费", "agg": "sum",   "field": "保费",
     "filters": [{"field": "险种", "op": "contains", "value": "车险"}]}
  ],
  "charts": [
    {"type": "trend", "title": "保费与佣金趋势", "metrics": [
        {"label": "保费", "agg": "sum", "field": "保费"},
        {"label": "佣金", "agg": "sum", "field": "佣金"}],
     "granularity": "month"},
    {"type": "donut", "title": "保司保费占比", "dimension": "保险公司",
     "metric": {"agg": "sum", "field": "保费"}, "top": 8},
    {"type": "bar", "title": "险种保费分布", "dimension": "险种",
     "metric": {"agg": "sum", "field": "保费"}}
  ],
  "ranking": {
    "title": "业务员业绩排行", "dimension": "业务员",
    "columns": [
      {"title": "保费", "agg": "sum", "field": "保费"},
      {"title": "佣金", "agg": "sum", "field": "佣金"},
      {"title": "提成", "agg": "sum", "field": "员工提成"},
      {"title": "保单量", "agg": "count"}
    ],
    "sort_by": "保费"
  }
}
```

- `agg`：sum / count / avg
- `filters[].op`：contains（包含）/ eq（等于）/ ne（不等于）/ not_contains（不包含）
- `field` 取值 = 台账导出列名（含公式字段），前端下拉从现有字段配置接口取

| `web/templates/insurance.html` | **不新建页面**：在现有顶部页面级 Tab（首页（台账记录）/ 数据看板 / 续保管理系统）中新增「销售看板」pageTab，enterprise / super_admin 可见（employee 不显示）；内部含三个二级 Tab：看板 / 看板配置 / 目标管理 |

前端交互约定：

- **新增/编辑操作一律用弹窗**（新增指标卡、新增目标、新增员工目标项等），弹窗顶部内置操作说明区（橙色提示框），说明该功能的用法与规则
- **每个数据带「?」图标**：指标卡、目标、图表标题、排行列头旁悬停展示数据来源与计算公式（内容取后端 `explain` 字段）

### API 设计

| 接口 | 方法 | 权限 | 说明 |
|------|------|------|------|
| `/api/insurance/dashboard/data` | GET | enterprise / super_admin | 返回聚合结果。参数：`date_start`、`date_end`；超管可带 `enterprise_id`。每个指标/目标/排行列附带 `explain` 字段（后端按配置自动生成说明文案：统计字段、聚合方式、筛选条件、时间范围、记录范围；公式字段附费率公式表达式），前端「?」悬停展示 |
| `/api/insurance/dashboard/config` | GET / PUT | enterprise（本企业）/ super_admin（任意企业 + global 模板） | 读取/保存看板配置；GET 返回 `{config, source: "enterprise"|"global"}`；企业管理员 PUT 时写 enterprise scope；带 `reset=1` 删除企业自定义恢复默认模板 |
| `/api/insurance/dashboard/fields` | GET | 同上 | 可选统计字段列表（数字类字段 + 维度字段），来源于现有字段配置 |
| `/api/insurance/dashboard/targets` | GET / POST / PUT / DELETE | enterprise / super_admin | 目标增删改查；员工目标支持「全员统一」批量接口（写 employee_name=NULL 记录）；`/data` 接口返回时附带各目标的实际值与完成率 |
| `/api/insurance/dashboard/salesmen` | GET | 同上 | 返回该企业台账「业务员」去重名单（供员工目标设置下拉） |

聚合范围：该企业 `status = 'done'` 且未删除的记录，时间按 `time_field`（默认签单日期，无值时回退创建时间）过滤。

### 权限控制

- `employee` 访问看板接口返回 403，前端员工账号不显示看板入口
- 企业管理员只能看/改本企业；超管顶部可切企业（沿用台账页现有企业切换交互）
- 超管额外能力：编辑 global 默认模板、按企业开关看板（`enabled`）
