## 一、结构性问题

### 1.1 缺少流程全景图

**现状**：文档直接进入细节步骤，读者无法快速把握全流程。

**建议**：在文档最前面增加一张流程总览表：

| 阶段 | 步骤 | 负责人 | 预计耗时 | 需客户配合 |
|------|------|--------|----------|------------|
| 信息收集 | 1.1-1.3 | 咨询客服 | 10分钟 | 提供保司信息、人员名单 |
| 系统配置 | 1.4-1.7 | 咨询客服（内部管理员操作） | 20分钟 | 确认企业名称、账号密码 |
| 模版定制 | 1.8 | 咨询客服 | 15分钟 | 提供台账Excel模版 |
| 验收测试 | （缺失） | 咨询客服+客户 | 10分钟 | 发送测试保单 |
| 持续跟进 | 第1-4周 | 咨询客服 | 每次5分钟 | 反馈识别问题 |

### 1.2 章节编号混乱

**现状**：
- 1.6 是"配置群聊监控"，但 1.6.1 和 1.6.2 实际讲的是"开通账号"和"配置自行注册用户"

**建议**：重新整理编号：


## 二、内容缺失

### 2.1 缺少"验收测试"环节（重要）

**现状**：配置完所有设置后，直接跳到"开始使用"，没有验证环节。

**建议**：在模版设置后、正式使用前新增一步：

> **验收测试**
> 1. 让客户在对接群内发送 1-2 份真实保单 PDF
> 2. 等待 1-2 分钟，在系统中刷新查看识别结果
> 3. 核对关键字段：承保公司、保单号、车牌号、险种、保费
> 4. 导出 Excel，确认格式与客户要求一致
> 5. ✅ 完成标志：客户确认识别结果和导出格式均符合预期

### 2.2 缺少"前置准备清单"

**建议**：在文档开头增加一个对接前需收集的信息清单，可以提前发给客户：

> **对接前请准备**：
> - 企业全称
> - 主要联系人姓名 + 手机号
> - 常投保的保司名称（3-5家）
> - 负责发送保单的微信号对应人员名单
> - 您现在使用的台账 Excel 模版（如有）
> - 是否需要自动计算佣金？如需要，请提供计算公式

### 2.3 缺少异常处理流程

**现状**：
- 1.3 提到"如果主流保司识别比较少，请联系技术客服"，但没有后续说明
- 客服不知道：联系谁？等多久？期间怎么跟客户说？

**建议**：每个需要技术介入的节点，补充：
- 联系方式（技术客服企微/群）
- 预计响应时间（如"3个工作日内完成训练"）
- 给客户的临时话术（如"训练期间已支持的保司可正常使用，训练完成后会通知您"）

### 2.4 缺少常见问题 FAQ

**建议**：在文档末尾增加一节"常见客户疑问及应答话术"，例如：
- "识别出错了怎么办？" → 截图发到对接群，我们会在 24 小时内修正
- "可以换台账格式吗？" → 随时可以调整，联系客服即可
- "新来的同事怎么加账号？" → 可自行注册，注册后联系我们激活
- "试用期到了怎么续费？" → 提前一周会通知，系统内可直接购买套餐

## 三、可读性问题（非技术客服视角）

### 3.1 专业术语未解释

| 原文术语 | 建议改为 |
|----------|----------|
| 群聊ID | 群聊编号（每个微信群在系统中的唯一标识，在辅助网站点击群头像可复制） |
| 发送人ID | 微信用户编号（在辅助网站中点击用户头像可复制） |
| 监控配置 | 群聊绑定设置（让系统自动接收指定群内的保单PDF） |
| 绑定发送人 | 关联微信账号（将系统账号与微信号对应，用于区分谁发的保单） |

### 3.2 操作步骤散落，来回跳转

**现状**：1.6（配置群聊监控）和 1.6.1（开通账号-绑定发送人）都要用到辅助网站 `wxbot.wuhuxiche.com/monitor`，但分别在不同章节说明，客服需要来回翻。

**建议**：
- 方案A：把辅助网站操作单独抽成一个附录卡片，标注"需要获取群聊编号或微信用户编号时，统一在此操作"
- 方案B：在首次提到辅助网站时完整说明操作方法，后续引用时写"参见步骤 2.4 中获取编号的方法"

### 3.3 截图缺少标注说明

**现状**：截图用红色箭头标注了操作位置，但没有编号和文字说明。

**建议**：
- 每张截图加编号（图1、图2...）
- 在截图下方加一句操作说明，如"图3：点击「+添加企业」按钮，在弹窗中填写企业名称"
- 红色箭头旁建议加数字编号（①②③），对应下方操作步骤

### 3.4 每个关键步骤缺少"完成标志"

**现状**：客服做完一步后，无法确认是否操作成功。

**建议**：在每个关键配置步骤后加确认方式，例如：
- 创建企业 → ✅ 企业管理列表中能看到新企业，状态为"启用"
- 开通套餐 → ✅ 企业行中"套餐"列显示对应套餐类型和到期日
- 配置群聊监控 → ✅ 监控配置列表中出现新配置，状态开关为"已启用"
- 开通账号 → ✅ 账号管理中新用户状态为"启用"
- 绑定发送人 → ✅ 让客户在群内发一份 PDF，1-2 分钟后在系统中能看到记录

## 四、准确性和细节问题

### 4.1 套餐试用期说明不完整

**现状**："套餐免费试用2个月，功能和正式购买套餐使用毫无区别"

**缺失信息**：
- 试用期从何时开始？（从创建企业当天？从开通套餐当天？）
- 试用期到了如果不续费会怎样？（数据保留多久？功能是否完全关闭？）
- 试用期内有识别次数限制吗？

**建议**：补充完整说明，避免客服被客户追问时答不上来。

### 4.2 辅助网站密码写在正文中

**现状**：`https://wxbot.wuhuxiche.com/monitor 密码为 wuhu2025`

**风险**：如果 SOP 文档流出，密码也会泄露。

**建议**：
- 密码不要写在 SOP 正文，改为"密码请咨询技术客服"或"密码见内部密码表"
- 或者使用独立的登录方式（如企微SSO）替代固定密码

### 4.3 "一份PDF为一个计算单位"需补充说明

**建议**：补充以下细节：
- 手动上传和群内自动识别都算一次？
- 识别失败的算不算一次？
- 重新识别算不算新的一次？

这些是客户必问的问题，客服需要有标准答案。

### 4.4 系统截图中出现了真实客户数据

**现状**：截图中可见真实企业名称（欧阳总公司、深圳市宏鑫保险代理有限公司等）、手机号、用户名。

**建议**：正式文档中使用脱敏后的演示数据截图，避免泄露客户信息。

## 五、老板/管理视角建议

### 5.1 增加对接耗时和成本预估

在文档开头写明：
> 一次标准新客户对接约需 **45-60 分钟**客服时间，其中约 20 分钟需要客户在线配合。

### 5.2 增加关键指标

跟进阶段不应只是"询问识别情况"，建议改为可量化的检查：
- 登录系统，查看该企业近7天识别记录
- 关注识别成功率（成功数 / 总数）
- **失败率 > 10%**：主动联系技术客服排查
- **失败率 > 30%**：升级处理，可能需要针对该客户主流保司做训练

### 5.3 增加对接完成度检查表

客服做完全部步骤后，对照勾选：

```
□ 企业已创建并启用
□ 套餐已开通（类型：___，到期日：___）
□ 对接微信群已建立（群内有：咨询客服 ✓ 技术客服 ✓ 客户人员 ✓）
□ 群聊监控已配置并启用
□ 用户账号已开通（共___个，角色分配已确认）
□ 发送人ID已绑定
□ 导出模版已按客户要求配置
□ 别名/佣金/日期格式已配置（如需要）
□ 验收测试通过（客户确认识别结果和导出格式正确）
□ 已告知客户反馈渠道和后续跟进计划
```

## 六、文字和排版优化

### 6.1 标点和断句

**现状**：多处缺少标点，读起来费劲。例如：
> "询问客户通过什么方式联系到我们的（来决定是否需要简单的介绍一下我们的系统）"

**建议**：加上标点断句，控制每句话不超过 30 字：
> "询问客户是通过什么渠道联系到我们的。根据回答，决定是否需要先简单介绍一下系统。"

### 6.2 用"你"还是"我们"要统一

**现状**：有时说"我们"（"我们来训练"），有时说"你"（"左手边就是刚才你为客户创建的群聊"）。

**建议**：统一用第二人称"你"，面向执行者。

### 6.3 关键操作用加粗或高亮

**现状**：重要操作和普通说明混在一起，不易区分。

**建议**：
- **操作动作**加粗：如"点击**添加企业**按钮"
- **注意事项**用⚠️标记
- **验证步骤**用 ✅ 标记

## 七、总结：优先级排序

| 优先级 | 修改项 | 原因 |
|--------|--------|------|
| 🔴 高 | 修正章节编号（1.6.1/1.6.2→归属1.7） | 当前编号混乱，客服执行容易跳步 |
| 🔴 高 | 新增"验收测试"环节 | 没有验收就交付，问题会在使用阶段集中爆发 |
| 🔴 高 | 术语加注释 | 非技术客服看不懂ID、监控等概念 |
| 🟡 中 | 增加流程总览表 | 老板和新客服需要快速了解全貌 |
| 🟡 中 | 增加完成标志 | 客服无法确认每步是否成功 |
| 🟡 中 | 补充异常处理和FAQ | 客服遇到问题不知道怎么办 |
| 🟡 中 | 截图脱敏 | 存在客户信息泄露风险 |
| 🟡 中 | 套餐试用期说明补全 | 客户必问，客服答不上来 |
| 🟢 低 | 辅助网站密码脱敏 | 安全优化 |
| 🟢 低 | 标点断句优化 | 可读性提升 |
| 🟢 低 | 前置准备清单 | 提升对接效率 |
| 🟢 低 | 跟进阶段量化指标 | 从"感觉"变成"数据驱动" |
