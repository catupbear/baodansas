# 保单识别集成方案

## 一、需求概述

将 baoxianOcr（保单识别）项目集成到 wxbot 中，实现：
1. 指定企业微信群内收到的 PDF，自动触发保单识别
2. PDF 上传至腾讯云 COS 存储桶（按 `群ID/发送人ID/文件名.pdf` 归类），避免文件落地服务器
3. 识别完成后，结果自动同步到指定的钉钉多维表格
4. 保留原有手动上传 PDF 识别功能，独立页面访问

## 二、整体流程

```
企微群收到PDF
  → 回调通知 → fetcher 拉取消息
  → 判断：是否为「监控群」的 file 类型 & .pdf 后缀
  → 是 → 投入处理队列（Queue，串行消费，控制内存）
  → 队列消费线程：
      → SDK 下载媒体文件到内存（限制单文件 ≤ 20MB）
      → 上传 COS（不落盘）
      → pdfplumber 从内存字节流提取文本
      → 提取失败 → 百度 OCR 兜底
      → policy_parser 解析保单字段
      → field_mapping 字段映射
      → dingtalk_table 同步到钉钉多维表格
      → 记录识别结果到数据库
      → 释放内存（del bytes + gc）
```

## 三、关键设计决策

### 决策1：内存控制（已确认）

**方案：队列串行处理 + 单文件大小限制**

```python
import queue
import threading

class InsuranceHandler:
    def __init__(self):
        self._queue = queue.Queue(maxsize=100)  # 最多排队100个
        self._worker = threading.Thread(target=self._consume, daemon=True)
        self._worker.start()
    
    def enqueue(self, msg):
        """非阻塞投入队列，队列满则丢弃并记录"""
        try:
            self._queue.put_nowait(msg)
        except queue.Full:
            logger.warning("保单识别队列已满，丢弃消息 seq=%s", msg["seq"])
    
    def _consume(self):
        """单线程串行消费，内存峰值 ≈ 单个PDF × 3"""
        while True:
            msg = self._queue.get()
            try:
                self._process(msg)
            except Exception as e:
                logger.error("保单识别失败: %s", e)
            finally:
                self._queue.task_done()
```

**内存分析：**
- 串行处理 → 同一时刻只有 1 个 PDF 在内存
- 单个 5MB PDF ≈ 占用 15MB（原始 + COS上传 + pdfplumber解析）
- 处理完立即 `del` 释放

**大文件降级策略：**
- ≤ 20MB → 内存处理（不落盘，常规路径）
- \> 20MB → 写临时文件处理，完成后立即删除临时文件

```python
import tempfile, os

if filesize <= 20 * 1024 * 1024:
    # 内存处理
    pdf_bytes = sdk_download_to_memory(sdkfileid)
    cos_upload(pdf_bytes)
    ocr_result = pdfplumber_extract(BytesIO(pdf_bytes))
    del pdf_bytes
else:
    # 大文件：临时文件处理
    with tempfile.NamedTemporaryFile(suffix=".pdf", delete=False) as tmp:
        tmp_path = tmp.name
        sdk_download_to_file(sdkfileid, tmp)
    try:
        cos_upload_from_file(tmp_path)
        ocr_result = pdfplumber_extract_from_file(tmp_path)
    finally:
        os.unlink(tmp_path)  # 处理完立即删除
```

### 决策4：识别结果存储

```sql
CREATE TABLE insurance_records (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    msg_seq INTEGER,                    -- 关联 messages 表（自动识别时有值）
    roomid TEXT,                        -- 来源群（手动上传时为空）
    room_name TEXT,                     -- 群名称
    sender TEXT,                        -- 发送人ID
    sender_name TEXT,                   -- 发送人名称
    filename TEXT,                      -- 原始文件名
    cos_url TEXT,                       -- COS 存储地址
    ocr_engine TEXT,                    -- pdfplumber / baidu
    doc_category TEXT,                  -- 商业险 / 交强险 等
    confidence REAL,                    -- 识别置信度
    parsed_fields TEXT,                 -- 解析后的字段JSON
    mapped_fields TEXT,                 -- 映射后的字段JSON
    dingtalk_synced INTEGER DEFAULT 0,  -- 是否已同步钉钉
    dingtalk_target_id TEXT,            -- 同步目标ID
    dingtalk_record_id TEXT,            -- 钉钉记录ID
    status TEXT DEFAULT 'pending',      -- pending/processing/success/failed/skipped
    error_message TEXT,                 -- 失败原因
    source TEXT DEFAULT 'auto',         -- auto（群自动）/ manual（手动上传）
    created_at TEXT,
    updated_at TEXT
);
```

## 七、风险点

1. **SDK 媒体 3 天有效期** — 队列积压不能超过 3 天，否则无法下载
2. **百度 OCR 配额** — 标准版有 QPS 和日调用量限制
3. **钉钉 API 频率限制** — 批量同步需控制节奏
4. **policy_parser.py 维护** — 1700+ 行，50+ 保险公司规则，需持续维护

## 八、实施步骤

1. **Phase 1 - 基础集成**
   - 创建 `insurance/` 模块目录
   - 迁移核心文件并适配接口
   - 新增数据库表（insurance_records, insurance_config）
   - 实现队列处理框架

2. **Phase 2 - 自动识别流水线**
   - fetcher 中增加 PDF 触发逻辑
   - SDK 下载 → 内存 → COS 上传（按 roomid/sender/filename 归类）
   - pdfplumber / 百度 OCR 识别
   - 解析 + 字段映射

3. **Phase 3 - 钉钉同步**
   - 迁移钉钉同步模块
   - 识别完成后自动同步
   - 保单号去重

4. **Phase 4 - 独立前端页面**
   - `/insurance` 页面（手动上传 + 自动记录 + 设置管理）
   - 群名显示、状态筛选、重试操作
   - 钉钉目标管理、字段映射配置

5. **Phase 5 - 管理 API**
   - 配置 CRUD（监控群、钉钉目标、OCR 配置）
   - Excel 导出
   - 统计接口
