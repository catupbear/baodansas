# 2026-07-20 16:00 更新记录

## 需求说明

围绕「AI 大模型质检」模块的一次体验与能力优化，包含 4 部分：

1. **修复「测试连通」按钮点击无反应**：AI 大模型管理弹窗中，**新增但尚未保存**的模型点「测试连通」毫无反应（已保存模型正常）。
2. **单条 AI 质检并入预览弹窗**：左看保单原件、右看质检结果，同屏对照；质检时显示进度与当前保单名；历史质检过的直接看结果，没质检过的才触发质检，并支持重新质检。
3. **AI 质检字段补全**：对比表覆盖解析器全部字段（此前只比对配置的核心子集）。
4. **批量 AI 质检**：勾选多条记录批量逐条质检，浮窗显示进度；完成后不自动弹窗，用户在列表点「AI质检」查看各条结果。

## 根因说明

- **测试连通 bug**：列表行显示状态读 `aiTestState[m.id]`，而 `testAiModel` 存到 `m.id || ('__row_' + index)`。新增未保存模型 `id` 为空字符串，状态存到了 `__row_N`，模板永远读不到 → 「测试中/结果」不显示，看起来点击无反应。
- **字段少**：手动质检后端其实已按 `FIELD_ORDER` 全字段比对；但**查看历史结果**时，`ai_check_log` 只存了 `diff_json`（差异字段），缺完整 AI 提取结果，历史只能还原差异那几个字段。

## 数据库变更

`ai_check_log` 表新增列（幂等 `ALTER`，随 `init_ai_tables` 自动执行，run_ocr.py / main.py 两入口共用，无需手动执行）：

```sql
ALTER TABLE ai_check_log ADD COLUMN extracted_json LONGTEXT
  COMMENT '本次AI提取的完整字段JSON(全字段历史对比用)';
```

## 追加迭代（同日 16:40）

用户走查后的补充需求与 bug 修复：

### 1. 已质检记录按钮改名「AI质检结果」
- `insurance/db.py`：列表查询 `query_insurance_records` 增加 `has_ai_check` 标记（`EXISTS` 子查询：该记录是否有含完整提取结果的质检流水）。
- 前端 `aiCheckedDone(record)`：据 `has_ai_check`（兜底 `ai_check_status`）判断，列表行/预览头部按钮显示「AI质检结果」或「AI质检」。

### 2. 应用AI值「无提示 + 应用无效」修复（重要）
根因两处：
- **提示被遮挡**：预览为全屏弹窗，全局 toast 被盖住 → 应用结果改为面板**内联提示**（`previewAiCheck.applyMsg`，绿/红）。
- **历史结果应用不生效**：
  - `insurance/api.py` 应用接口 `ai_extract_apply`：历史对比按实时列表值重算，勾选字段可能不在质检当时的 `diff_json` 里 → AI 值改为**优先取 `extracted_json`（完整提取）**，回退 `diff_json`；已一致的跳过。
  - 应用AI值改为**加入 `manual_fields`**（原逻辑是移除）：部分企业（如文十七 id=24）会剔除「禁用自动识别」的字段（业务员/销售渠道），仅 `manual_fields` 例外，原逻辑导致应用值被剔除、列表值无变化。
  - `insurance/db.py` `update_insurance_record`：剔除判断此前只读 DB 旧 `manual_fields`，**同批次新增的手动字段会被误剔除** → 改为并入本次 `updates` 传入的 `manual_fields` 一起判断。修复后应用值可正确落库并映射到输出列（如 销售渠道→出单渠道）。

### 3. 应用历史记录（排查用）
- 预览 AI质检面板底部新增可折叠「应用历史」，展示 `ai_corrections`：字段、原值→新值、时间、操作人、来源（手动应用/自动修正）。
- `loadPreviewAiCheckHistory` 一并读取接口返回的 `ai_corrections`；应用成功后重拉刷新。

### 验证（API + UI 实测）
- 应用后字段值真正落库（`parsed_fields['销售渠道']='个人代理'`、`display_fields['出单渠道']='个人代理'`），该字段从「差异」移到「一致」，不再残留勾选。
- 已质检记录列表按钮显示「AI质检结果」；未质检显示「AI质检」。
- 历史面板显示「历史结果·模型·时间」，应用历史可展开查看。

### 4. 字段「数据来源」标注（仅超管）
- 预览「列表信息」面板每个字段值旁显示来源小标签，仅 `isSuperAdmin` 可见。
- `fieldSource(key)` 判定优先级：**AI质检识别**（`ai_fields`）>**手动修改**（`manual_fields`）>记录识别引擎（含 ocr/百度/火山→**OCR提取**，pdfplumber/空→**PDF提取**）。
  - AI 优先于手动：应用AI值会同时写入两个列表，故 AI 先判。
  - PDF vs OCR 为整条记录引擎级别（解析器跑 PDF 文本或 OCR 文本），非逐字段。
  - `key` 为导出列名，匹配时并入映射到该列的 OCR 字段名（`default_mapping`）。
- 空值字段与记录级字段（文件名/状态/创建时间/群名等）不显示来源。
- 预览详情加载补充解析 `ai_fields` 为数组（原只解析 `manual_fields`）。

### 5. 手动质检并入质检看板（原只统计自动质检）
用户反馈：手动质检的数据在「AI质检看板」看不到。根因：企业统计只算 `trigger_type='auto'`，问题列表只查 `ai_check_status` 非空的记录，而手动质检从不回写状态。改动：
- `insurance/api.py` `ai_extract_record`（手动质检）：结果与自动质检**统一口径**——有差异→`flagged`(待确认)、无差异→`pass`(通过)，回写记录 `ai_check_status`/`ai_checked_at` 并写入流水 `result`。
- `insurance/api.py` `ai_extract_apply`（应用AI值）：流水 `result` 与记录状态置为 `corrected`（已修正），移出待确认。
- `insurance/api.py` `get_record_ai_check_detail`：历史对比流水筛选改为**只按 `extracted_json` 是否存在**（不再限定 result=extracted/applied，兼容新口径）。
- `insurance/ai_db.py` `get_ai_check_stats`：`trigger_type` 由 `='auto'` 改为 `IN ('auto','manual')`，企业统计计入手动质检的质检数/修正数/AI成本/高频出错字段。

效果（实测）：手动质检记录进入「质检问题列表」（待确认）+ 顶部待确认红点，企业质检统计的质检数/成本计入手动质检。
