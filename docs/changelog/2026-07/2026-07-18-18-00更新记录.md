# 2026-07-18 更新记录：AI质检（手动AI质检 + 按企业自动质检）

## 需求说明

设计方案见 `docs/design/AI识别与AI质检方案.html`（已确认）。

1. **手动AI质检（功能一，仅内部超管）**：识别出错时，超管在操作列/预览弹窗点「AI质检」，用国产多模态大模型直接读 PDF 原件提取字段，弹窗三列对比差异后勾选覆盖。AI 结果不自动落库，必须人工确认；每次点击必写流水（无论是否应用）。
2. **AI自动质检（功能二，按企业开启）**：识别完成后按企业配置自动用大模型复核提取结果。质检范围支持多条件（状态多选：非保单/需人工补充/识别异常/识别失败/正常完成；保司多选；保司历史识别数 < 阈值），条件为「或」关系，不使用置信度、不限质检额度。发现差异按「AI直接覆盖」双层开关（全局总闸 且 企业开关，均默认关）决定直接覆盖或仅标记，全部差异进系统内「AI质检问题列表」处理，并发钉钉机器人通知（webhook 后台可配置，留空回退系统告警机器人）。**不自动同步钉钉多维表**。
3. **多模型管理**：支持配置多个模型（通义/智谱/豆包/Kimi/混元预设 + 自定义 OpenAI 兼容端点），一个设为当前使用，失败按优先级自动降级，可一键切换；每次调用实际模型记入流水。
4. **企业质检统计**：按企业聚合质检数/准确数/修正数/待确认数/真实准确率/高频出错字段 TOP3/估算成本。

## 数据库变更（首次启动自动执行，幂等）

- `insurance_records` 新增列：
  - `ai_check_status` VARCHAR(16) — pass/corrected/flagged/resolved/error
  - `ai_fields` LONGTEXT — 被AI覆盖过的字段名列表 JSON
  - `ai_corrections` LONGTEXT — AI 修正历史（含原值备份，可还原）
  - `ai_checked_at` DATETIME
  - 索引 `idx_insurance_ai_check(ai_check_status)`
- 新表 `ai_check_log` — AI 调用流水（手动+自动共用；操作人、模型、结果、差异明细、token、耗时）
- `insurance_config` 新增 KV：
  - `ai_model_config` — {enabled, allow_auto_fix, models[], active_model_id, max_pages, cost_alert_threshold, notify_webhook, notify_secret, prompt_template}
  - `ai_check_enterprises` — {enterprise_id: {enabled, auto_fix, scope, compare_fields}}

## 代码变更

### 后端（新增）
- `insurance/ai_db.py` — AI 表结构 DDL、配置读写（API Key 打码/回填）、流水 CRUD、问题列表查询、企业统计聚合
- `insurance/ai_extractor.py` — PDF→pypdfium2 渲染图片→OpenAI 兼容多模态 API→JSON 字段；厂商预设；多模型按优先级自动降级；连通性测试（requests 裸调，不引厂商 SDK）
- `insurance/ai_checker.py` — 质检队列（独立守护线程串行消费）、范围条件匹配、字段归一化比对（金额/日期/车牌归一）、直接覆盖策略（人工字段永不覆盖；仅补充型或可在原文交叉验证的差异才自动改）、钉钉通知、日成本提醒

### 后端（修改）
- `insurance/db.py` — init 挂钩 AI 表初始化；列表查询补 `ai_check_status/ai_checked_at` 列
- `insurance/handler.py` — `_process` 识别完成/识别失败后入 AI 质检队列（异常不影响主流程）
- `insurance/api.py` — 新增接口（全部仅超管）：
  - `POST /api/insurance/ai-extract/<id>`、`POST .../apply` — 手动AI质检 + 应用勾选
  - `GET/PUT /api/insurance/ai-config`、`POST .../test` — 多模型配置 + 连通性测试
  - `GET/PUT /api/insurance/ai-check/enterprises` — 企业质检开关/范围配置
  - `GET /api/insurance/ai-check/issues`、`POST /api/insurance/records/<id>/ai-check/resolve` — 问题列表 + 处理（采纳/保留/还原）
  - `GET /api/insurance/records/<id>/ai-check`、`GET /api/insurance/ai-check/logs`、`GET /api/insurance/ai-check/stats`
  - 重识别成功时重置 `ai_check_status`（允许再次质检）
- `core/notify.py` — 新增 `notify_ai_check()`（可配置 webhook，留空回退系统告警机器人）
- `requirements.txt` — 新增 `pypdfium2`、`Pillow`

### 前端（修改）
- `web/templates/insurance.html` — 操作列/预览弹窗「AI质检」按钮、AI对比弹窗（勾选覆盖）、质检状态徽标列+详情弹窗（可还原）、「AI质检」Tab（问题列表 + 企业统计）——全部仅超管可见
- `web/templates/field_config.html` — 「AI 模型」Tab：多模型列表管理（增删改/优先级/切换当前/测试连通）、全局开关、直接覆盖总闸、成本提醒、钉钉 webhook、Prompt 模板
- `web/templates/admin_enterprises.html` — 企业行 AI质检开关、AI直接覆盖开关（二次确认）、质检范围配置弹窗

## 兼容性

- 全部为新增列/新表/新 KV/新接口，不改任何既有接口语义，老版本前端不受影响
- AI 总开关默认关闭：未配置模型前所有 AI 功能不生效，识别主流程行为与升级前完全一致
- 服务器未安装 pypdfium2 时，AI 提取返回明确错误提示，不影响其他功能

## 部署步骤

1. 上传后端文件：`insurance/ai_db.py`、`insurance/ai_extractor.py`、`insurance/ai_checker.py`、`insurance/db.py`、`insurance/handler.py`、`insurance/api.py`、`core/notify.py`、`requirements.txt`
2. 上传前端文件：`web/templates/insurance.html`、`web/templates/field_config.html`、`web/templates/admin_enterprises.html`
   （注意：/insurance 线上是 nginx 静态文件，insurance.html 需同步传 `/home/wxbot/web/static/insurance.html`）
3. 服务器安装依赖：`pip install pypdfium2 Pillow`
4. gunicorn --reload 自动生效；首次请求时自动建表/加列
5. 系统设置 → AI 模型：添加模型（建议 qwen-vl-max 主力 + 豆包 vision 备用）、开启总开关、配置钉钉通知 webhook
6. 客户管理：按企业开启 AI 质检（建议先「仅标记」跑两周，准确率验证后再开「AI直接覆盖」）
