## 代码变更

### `/Users/take/Downloads/yun/web/wxbot/task_group_sync.py`

- `CorpClient.list_customer_groups()`：客户群列表 API 翻页拉取（limit 1000/页，游标翻页，0.3s 限速）；
- `run_list_discovery()`：各企业客户群列表 → 新 chat_id 以 pending 插入（`insert_room_ids`），随即触发一轮增量解析补齐群名详情；
- 主循环新增列表发现调度：默认**每天 1 次**，启动时先跑一轮；配置 `group_sync.list_interval`（秒），设 0 关闭。
- 前提：企业需配置 `external_secret` 且「客户联系」应用可见范围覆盖群主，否则该企业跳过（打日志不报错）。

### `/Users/take/Downloads/yun/web/wxbot/storage/group_db.py`

- 新增 `insert_room_ids(db, roomids, corpid, group_type)`：批量 INSERT IGNORE，供列表发现使用。

### `/Users/take/Downloads/yun/web/wxbot/core/contacts.py`（群名职责移交）

- `get_room_name()`：优先读 wecom_groups（群改名后拿到的是最新值），未覆盖的才走原 contacts_cache/API 链路——消息监控页等所有残余调用点自动统一；
- `batch_resolve()`：群名先一次批量查 wecom_groups，再 contacts_cache，最后现场解析；
- `find_unresolved()`：wecom_groups 已有群名的群不再重复解析——contacts_cache 的群名条目自然停止新增（存量保留，人名逻辑完全不变）。

### `/Users/take/Downloads/yun/web/wxbot/main.py`

- `init_group_table` 提前到 ContactsManager 初始化之前（通讯录自动解析线程会 JOIN 该表，避免首轮建表竞态）。

### `/Users/take/Downloads/yun/web/wxbot/web/templates/insurance.html`

- 删除台账下拉加载时对 `/api/contacts/resolve` 的补偿调用（后端接口保留，兼容旧版本前端）。
