# 群内补充命中0条时机器人通知 @发送人 + @技术客服

## 需求说明

群内发送补充信息文本（车牌 + 业务经理/业务专员/保险公司经办人等）时，若按车牌在系统中
**找不到任何已识别的保单记录**（政策回填命中0条），补充信息会被直接丢弃、只记日志，
发送人毫无感知。

本次新增：命中0条时，通过 FlowBot 机器人向该群发送提示消息，同时 @发送人 和
@技术客服（午虎保单台账系统），引导发送人自查并在保单识别成功后重发补充信息。

触发案例（午虎科技群 seq=35455）：

```
车牌:粤E-R705I
业务经理：孔婉琳
业务专员:孔婉琳
保险公司经办人: 成成
→ 政策回填: 命中0条，信息被丢弃且无任何提示
```

## 通知文案（默认模板）

> @发送人 @技术客服（午虎保单台账系统）
> ⚠️ 补充信息未录入
> 车牌：{plate}
> 系统暂未找到该车牌的保单识别记录，本次补充的信息（业务经理、业务专员、保险公司经办人等）未能生效。
> 请检查：
> 1️⃣ 该车牌的保单是否已发到本群并识别成功
> 2️⃣ 车牌号是否输入有误
> 确认保单已识别后，请重新发送一次补充信息即可。
> 若车牌无误但仍提示未录入，请联系客服处理（已@技术客服跟进）。

`{plate}` 动态替换为解析到的车牌；@ 通过 FlowBot atList 实现（非文本内容）。

## 数据库变更

无表结构变更。新增 `insurance_config` 配置键 `quote_fill_miss_notify`：

```json
{
  "enabled": true,
  "robot_id": "",
  "tech_support_name": "技术客服（午虎保单台账系统）",
  "template": ""
}
```

- `enabled`：开关，**默认关闭**，需手动开启
- `robot_id`：可选，缺省复用 `flowbot_fail_notify` 配置的机器人 ID
- `tech_support_name`：可选，要 @ 的技术客服微信名（须与微信昵称完全一致，FlowBot 按名匹配）
- `template`：可选，自定义文案，`{plate}` 为车牌占位符

## 代码变更

| 文件 | 变更 |
|------|------|
| `/Users/take/Downloads/yun/web/wxbot/core/fetcher.py` | `_check_policy_fill_trigger` 中命中0条时调用新增方法 `_notify_policy_fill_miss`；新增默认文案常量 `_POLICY_FILL_MISS_TEMPLATE` |

实现要点：

- 仅在文本被判定为"补充信息文本"（有车牌 + 至少一个有值字段）且命中0条时触发，
  普通聊天不受影响
- 复用现有 `insurance/flowbot_notify.py` 的 `send_flowbot_group_message`（atList 传多人）
- 群名/发送人微信名通过 `handler.contacts` 解析，与台账导出触发链路一致
- 旁路通知：任何异常只记日志，绝不影响消息拉取主流程

## 部署步骤

1. 上传 `core/fetcher.py` 到服务器 `/home/wxbot/core/fetcher.py`（gunicorn 热更新，无需重启）
2. 开启配置（二选一）：
   - API：`PUT /api/insurance/config`，请求体
     `{"quote_fill_miss_notify": {"enabled": true, "tech_support_name": "技术客服（午虎保单台账系统）"}}`
   - 或直接写 `insurance_config` 表
3. 确认 FlowBot 机器人已在目标群内，且「技术客服（午虎保单台账系统）」与其微信昵称完全一致
4. 群内发一条不存在车牌的补充文本验证通知效果

## 注意事项

- 命中0条时补充信息仍会被丢弃（本次未做"待补暂存、识别后自动回填"，如需后续再做）
- FlowBot @ 人按微信名匹配，技术客服昵称若改名需同步更新 `tech_support_name`
