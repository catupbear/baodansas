# 修复：客户群改名事件回调收到后拉不到群名（event_callback.secret 配错）

## 问题现象

企业微信客户群修改群名后，系统里的群信息不更新。

## 排查结论

分两个阶段定位：

1. **事件根本没推送**（前期）：应用日志里只有 URL 验证（GET），从无 `change_external_chat` 的 POST 事件。原因是自建应用「午虎科技」(AgentId 1000002) 未在企业微信「客户联系」里授权可调用接口的应用 + 勾选「外部联系人变更回调」。后台补齐授权后，事件开始正常推送：
   `type=change_external_chat, ChangeType=update, UpdateDetail=change_name`
   （本次新增的 `UpdateDetail=change_name` 精确过滤逻辑工作正常）

2. **收到事件后拉群详情报 48002**（根因）：`event_callback.secret` 配成了一个**没有客户群接口权限**的 secret（`okliWgS9...`），调用 `externalcontact/groupchat/get` 返回 `48002 api forbidden`，导致取不到群名而跳过。

   对比验证：
   | secret | gettoken | groupchat/list |
   |--------|----------|----------------|
   | 错配 `okliWgS9...` | ok | **48002 无权限** |
   | 正确 `mRBDOanv...` | ok | **errcode=0，79 个群** |

   正确 secret（`mRBDOanv...`）其实项目里 `extra_callbacks`「午虎科技」的 `external_secret` 早已在用，只有 `event_callback.secret` 错配。

## 变更内容

- **配置**（服务器 `/home/wxbot/config.yaml`，该文件已 gitignore 不入库）：
  `event_callback.secret` 由 `okliWgS9...` 改为 `mRBDOanv...`（与「午虎科技」应用一致、具备客户群接口权限）。
- **代码**：无。`core/contacts.py` 与 `callback/event_callback.py` 逻辑均正确，无需改动。

## 验证

- 用正确 secret 直接调 `externalcontact/groupchat/get` 目标群：`errcode=0`，成功取到群名。
- 部署方式：修改服务器 config 后 `kill -HUP` 平滑重载 gunicorn（master 不变、worker 零停机替换）。
- 待用户再次改名做一次重载后的端到端回调验证。
