# FlowBot 送达结果回调接入（推送日志落库 + 失败自动重发 + 掉线告警）

## 需求说明

FlowBot `sendTask` 的 `code=200` 只代表"指令已接收"（异步执行），不代表真实送达，
之前发出后无从得知是否成功。本次参考 wuhuApi 项目的成熟实现
（文档 https://flowbot.apifox.cn/doc-5369842 ）接入 FlowBot 回调：

- **发送落库**：每次群通知发送成功后，把 taskId + 原始 payload 写入
  `flowbot_push_log` 表（状态=推送中）
- **执行回调**（mode=callBack）：按 taskId 更新真实结果——
  - `success` → 标记推送成功
  - `fail` → 用原 payload 自动**重发，最多 3 次**（更新为新 taskId 继续跟踪）；
    额度用尽 → 标记最终失败 + **钉钉告警**（群名、消息摘要、失败原因）
- **机器人掉线**（mode=offline）→ 钉钉告警提醒检查手机/登录状态
- 其余 mode（init/receipt/online/logs）只记日志；聊天记录 logs 量大记 debug

回调端点 3 秒内应答 `{"code":200}`，耗时逻辑（重发/告警）放后台线程。

## 数据库变更

新增表 `flowbot_push_log`（首次启动自动建表）：

| 字段 | 说明 |
|------|------|
| task_id | FlowBot 任务ID（索引；重发后更新为新ID） |
| robot_id / group_name / message | 机器人、目标群、消息正文 |
| payload | 发送任务 taskList JSON（失败重发用） |
| status | 0=推送中 1=成功 2=失败 |
| retry_count | 回调失败后的重发次数（上限3） |
| error_msg | 失败原因 |

## 注意事项

- 两级重试并存：sendTask 接口调用失败重试3次（同步，flowbot_notify）；回调返回
  执行失败再重发最多3次（异步，flowbot_callback），两者叠加覆盖不同故障层
- 注册回调后，飞流会把该机器人的聊天记录（logs）也推过来，端点只记 debug 日志，
  不做业务处理（消息来源仍以会话存档为准）
- 端点无鉴权（与 wuhuApi 一致），依赖 URL 保密性；后续如需可加 robotId 白名单校验
