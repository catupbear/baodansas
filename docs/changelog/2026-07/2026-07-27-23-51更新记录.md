线上识别永安财险交强险电子保单（样例：`钟建文_桂A8A5D7_永安财险_交强险_345012603010024878.pdf`）时大量字段错位或漏抽：

## 根因

该版式的 PDF 文字层是「模板标签层」与「数值层」分离的：pdfplumber 抽出的文本中，表格标签连排且旁边无值（如"发动机号码 核定载客 核定载质量"），真实值集中在"保险单号：xxx"之后的数值块中逐行出现。按标签就近取值的通用正则因此全部错位或落空。

## 代码变更

`insurance/policy_parser.py`

- 新增 `_fix_yongan_compulsory_layered(text, fields)`：按数值块强锚点重抽并覆盖错位值
  - 数值块起点锚定"保险单号：xxx"行，依次取被保险人、身份证号、「号牌 机动车种类 使用性质」同行、厂牌型号（VIN 上一行）、车架号VIN（17 位独占行）、「发动机号 核定载客 核定载质量」（VIN 下一行）、「排量 功率 登记日期」行
  - 争议解决方式取数值层独占行的"诉讼/仲裁"
  - 车船税取「大写金额 + 唯一一个数字」行（保费行后跟多个数字不会误中）
  - 保司名称/地址取落款"永安财产保险股份有限公司xx分公司"行及其下一行
  - 交强险单仅载被保险人，投保人回填为同一主体并互补身份证号
- `_extract_common_fields` 末尾增加触发调用，三重门槛：保司=永安 + 险种含"强制" + 文本命中"发动机号码\s+核定载客"相邻标签特征；不满足则完全不生效，对其他保司及正常版式永安保单零影响

## 追加修复（2026-07-28 00:05）

首次部署后线上重识别发现发动机号仍错：**服务器的 pdfplumber 版本与本地不同，会吞掉表格单元格间的空格**，同一行本地提取为 `K581305 5 0千克`，线上提取为 `K58130550千克`；车船税行线上为 `叁佰陆拾元整 360.001.本保单销售渠道…`（金额与后续条款文字粘连）。追加两处兼容：

- 发动机号行：有空格版匹配失败后，按粘连版拆分（发动机号贪婪取最长 + 核定载客限 1-2 位不以 0 开头 + 核定载质量限 0 或 ≥3 位真实重量，回溯后得唯一解）
- 车船税：不再用行尾锚点，收集所有「大写金额+数字」候选行，剔除与保费合计相同的金额后取最后一条

两种版式（本地 PDF 提取文本 + 线上库存 raw_text）各 23 项断言全部通过，已用线上原文在服务器上验证解析结果正确。

**经验**：验证 parser 规则必须用线上记录的 `raw_text`（库存原文），不能只用本地 pdfplumber 提取的文本，两者空格处理不一致。
