# 2026-07-18 车牌字母 I 被误归一化为数字 1 修复

## 需求说明

平安商业险保单《罗金生 商业险.pdf》车牌为 `粤E-R705I`（序号末位是字母 I），系统识别结果为 `粤ER7051`，字母 `I` 被错误替换成了数字 `1`。

**原因**：此前为修复 OCR 把车牌 `0` 误识为 `O` 的问题（commit e694d2b），新增了 `_normalize_plate()`，依据国标 GA 36-2018「车牌序号不含 I/O」无条件将序号中的 `O→0`、`I→1`。但该保单文本来自 pdfplumber 提取的 **PDF 文字层**（逐字精确、不存在误识），且现实中确实存在序号带 `I` 的车牌，归一化反而把正确结果改错了。

**修复方案**：给解析入口增加 `from_ocr` 参数（默认 `False`，向后兼容），只有文本来自 OCR 引擎（百度/火山）时才执行车牌易混字符归一化；PDF 文字层文本保持原文不做替换。

## 数据库变更

无。

## 代码变更

| 文件 | 变更 |
|------|------|
| `insurance/policy_parser.py` | `parse_policy_text` / `parse_policy_text_multi` / `_extract_common_fields` / `_extract_vehicle_info` 新增 `from_ocr=False` 参数并逐层透传；`_normalize_plate` 仅在 `from_ocr=True` 时调用 |
| `insurance/handler.py` | 4 处调用点按文本来源传 `from_ocr`：主流水线按 `ocr_engine != "pdfplumber"` 判定；OCR 补充解析、图片 OCR 解析、OCR 早停检查固定传 `True` |
| `insurance/api.py` | `/api/insurance/ocr` 两处调用点按 `ocr_engine` 传参；`/api/insurance/parse`（前端 pdf.js 文字层）保持默认 `False` |

**兼容性**：新参数带默认值，所有历史调用方（含 `spot-check-skill/scripts/spot_check.py`，读取 pdfplumber 文字层，默认 `False` 即正确）无需改动。OCR 路径的 `O→0`、`I→1` 归一化行为不变，原 commit e694d2b 修复不回退。

## 验证结果

```
文字层解析 粤E-R705I → 粤ER705I ✅（修复前为 粤ER7051）
OCR 解析   粤E-R705I → 粤ER7051 ✅（OCR 来源仍归一化，行为不变）
OCR 归一化 粤GO8O3R → 粤G0803R ✅（原 O→0 修复不回退）
```
