# 客户群变更回调：按 UpdateDetail=change_name 精确过滤群名修改

## 需求说明

企业微信「客户群变更事件」`change_external_chat` 的 `update` 类型会在任意群变更（加/退成员、改群主、改公告、改群名）时回调。原实现只要收到 `create`/`update` 就无条件调用「获取客户群详情」接口刷新群信息，导致大量与群名无关的变更也触发接口调用（该接口有频率限制）。

本次收紧触发条件：仅在**新建群**或**群名被修改**时才拉群详情。

## 数据库变更

无。

## 代码变更

**`callback/event_callback.py`**

- `receive_event()`：新增读取回调 XML 中的 `<UpdateDetail>` 字段，并将触发条件由
  `change_type in ("create", "update")` 收紧为：
  - `create` → 放行（新建群无 UpdateDetail，需拉详情建群）
  - `update` → 仅 `UpdateDetail == "change_name"`（群名修改）时放行
  - 其余 update 明细（`add_member` / `del_member` / `change_owner` / `change_notice`）不再触发详情接口调用
- 日志增加 `UpdateDetail=%s` 便于排查
- 头部 docstring 职责描述同步更新

对企业微信回调契约无影响（未识别事件仍一律返回 `success`，避免重试）。

## 部署步骤

后端源码变更，直接上传 `callback/event_callback.py` 到服务器，`kill -HUP` 平滑重载 gunicorn。
