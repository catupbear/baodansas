# 会话列表按群名搜索修复

## 需求说明

`/monitor/chat` 会话列表按群名搜索时，部分群（如「午虎保单台账-识别群（鹏杰华智能-TZ008）」）明明存在却搜不到。

## 问题根因

会话列表搜索在 `storage/db.py` 的 `get_conversations()` 里对 `messages` 表做 SQL 过滤，
关键词只匹配 `summary / sender / roomid` 三个字段。而群名是查询完成后在 API 层
（`web/api.py` 的 `batch_resolve`）从 `wecom_groups`（权威）/`contacts_cache`（兜底）贴上去的，
**群名根本不在 messages 表、也不参与搜索匹配**。

结果：按群名搜索时，只有当群名文字恰好出现在某条消息正文（summary）里才会偶然命中，
否则「群存在却搜不到」。

## 数据库变更

无。

## 代码变更

- `storage/db.py` `get_conversations()`：关键词搜索追加两个子查询条件，
  把命中 `wecom_groups.name` 或 `contacts_cache`（type='room'）群名的 roomid 一并纳入结果，
  与页面「群名以 wecom_groups 为权威、contacts_cache 兜底」的显示口径一致。

```sql
-- 原：
(summary LIKE %s OR sender LIKE %s OR roomid LIKE %s)
-- 改：
(summary LIKE %s OR sender LIKE %s OR roomid LIKE %s
 OR roomid IN (SELECT roomid FROM wecom_groups WHERE name LIKE %s)
 OR roomid IN (SELECT id FROM contacts_cache WHERE type = 'room' AND name LIKE %s))
```

## 验证

对线上库只读模拟新查询：搜「鹏杰华智能」由旧逻辑的偶然命中 1 个，变为稳定命中该 TZ008
的客户群 + 识别群共 2 个。

2. 上传本地 `storage/db.py`
