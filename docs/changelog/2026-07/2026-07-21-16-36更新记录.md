# 修复「质检问题列表」时间显示为 GMT 英文格式

## 需求说明

保单识别页面 `/insurance` 的「AI质检」Tab 下「质检问题列表」表格，"时间"列显示成
`Tue, 21 Jul 2026 16:01:16 GMT` 这种英文 RFC1123 格式，而非项目统一使用的
`2026-07-21 16:01:16` 格式，需要修复。

## 问题根因

后端 `insurance/ai_db.py` 的 `query_ai_check_issues()` 函数（供 `/api/insurance/ai-check/issues`
接口使用）用 `pymysql.cursors.DictCursor` 查出 `r.ai_checked_at` 字段后，**没有像其他同类查询函数一样
手动转成字符串**，而是把 MySQL DATETIME 对应的 Python `datetime` 对象原样塞进返回结果并 `jsonify()`。

Flask 默认的 JSON encoder 对未转字符串的 naive datetime 对象会用 `werkzeug.http.http_date()` 序列化成
RFC1123/GMT 格式，例如 `Tue, 21 Jul 2026 16:01:16 GMT`。这里的 `"GMT"` 标签具有误导性——
数值其实就是数据库里存的原始北京时间，**并没有做真正的时区换算**。

前端 `web/templates/insurance.html` 原来在「质检问题列表」表格里直接输出该字段
（`{{ issue.ai_checked_at || '—' }}`），未经任何格式化，导致直接暴露了这个英文 GMT 字符串。

已排查页面内其他 `created_at` 类似字段（佣金流水 `walletTransactions`、续保跟进 `renewalFollowups`、
内部备注 `internalNotesList`、AI质检详情弹窗的操作流水 `aiCheckDetailModal.logs`），确认对应后端函数
都已正确做了 `str()`/`strftime()` 转换，不存在同样问题，无需一并修改。

## 代码变更

### 1. 后端根因修复：`insurance/ai_db.py`

`query_ai_check_issues()` 查询结果 `rows` 组装完成后，新增一段循环，把 `ai_checked_at`
统一转成字符串（与项目里其他返回 datetime 字段的函数保持一致的写法）：

```python
for r in rows:
    if r.get("ai_checked_at"):
        r["ai_checked_at"] = str(r["ai_checked_at"])
```

### 2. 前端防御性格式化：`web/templates/insurance.html`

在 `formatTime()` 函数旁新增 `formatTimeSec()`，用于展示精确到秒、且能兼容两种输入的时间：

- 普通字符串（如 `"2026-07-21 16:01:16"` 或 `"2026-07-21T16:01:16"`）：直接截取前 19 位展示；
- RFC1123/GMT 格式字符串（如 `"Tue, 21 Jul 2026 16:01:16 GMT"`）：**不经过 `new Date()` 的本地时区
  getter**（那样会把这个"伪 GMT"字符串当成真 UTC 时间，再按浏览器时区二次偏移，导致显示错误），
  而是用正则直接从字符串里把年月日时分秒的数字抠出来拼接，完全不涉及时区转换，避免偏差。

「质检问题列表」表格的时间列改为调用该函数：

```html
<!-- 修改前 -->
<td>{{ issue.ai_checked_at || '—' }}</td>
<!-- 修改后 -->
<td>{{ formatTimeSec(issue.ai_checked_at) }}</td>
```

同时把 `formatTimeSec` 加入 Vue `setup()` 的 `return {...}` 导出列表，供模板使用。

## 数据库变更

无。

## 部署步骤

1. 上传 `insurance/ai_db.py`、`web/templates/insurance.html` 到服务器对应目录
   （`/insurance` 页面线上是 nginx 静态文件，需按项目约定传到 `/home/wxbot/web/static/insurance.html`，
   `insurance/ai_db.py` 传到 `/home/wxbot/insurance/ai_db.py`）。
2. `kill -HUP` 平滑重载 gunicorn 使后端改动生效；前端静态文件保存后即生效，无需重启。
3. 以上部署动作需先征得用户明确同意后执行，本次仅完成本地代码修改。

# 追加：AI质检面板新增「查看原始返回」按钮（展示大模型API原始返回值）

## 需求说明

保单识别页面 `/insurance` 预览弹窗里的「✨ AI质检 本次结果·千问/qwen3-vl-plus·耗时x.xs」对比面板
（对应前端 `previewAiCheck` 状态，字段/列表值/AI提取值/状态对比表），需要新增一个按钮，可以查看
「本次」大模型 API 调用的**原始返回值**（未解析的 HTTP 响应原文），便于排查模型输出异常、
JSON 解析失败等问题。

## 排查结论：原来完全没有落库/回传

`insurance/ai_extractor.py` 的 `call_vision_model()` 拿到模型响应后，只把解析出的 `answer`
（message.content 文本，用于内部错误提示）保留在函数内部，**从未把原始响应对外返回**；
上层 `extract_fields_from_pdf()` 只返回 `fields/model/prompt_tokens/completion_tokens/duration_ms/
fallback_used/errors`，同样没有原始响应。因此无论是手动质检接口
`POST /api/insurance/ai-extract/<record_id>`，还是质检流水表 `ai_check_log`，都没有保存过原始返回值，
必须新增字段、贯穿整条调用链。

## 代码变更

### 1. `insurance/ai_extractor.py`（新增数据来源）

- 新增常量 `_MAX_RAW_RESPONSE_LEN = 50000`，限制落库/回传的原始返回文本长度。
- `call_vision_model()`：在解析出 `answer` 之前，额外保留 `resp.text`（未解析的完整 HTTP 响应体文本），
  截断后作为 `raw_response` 一并放入返回字典：`{"fields":..., "usage":..., "raw":..., "raw_response":...}`。
- `extract_fields_from_pdf()`：把成功调用那次的 `raw_response` 一并放进最终返回字典，并更新了函数
  docstring 里的返回值说明。

### 2. `insurance/ai_db.py`（新增落库字段）

`ai_check_log` 表新增列迁移（幂等 `ALTER TABLE ADD COLUMN`，与 `extracted_json` 列同一批处理）：

```python
("raw_response", "LONGTEXT COMMENT '大模型API原始返回文本(未解析,供排查用)'"),
```

`insert_ai_check_log()`/`update_ai_check_log()` 本身是按 dict key 动态拼列名的通用写法，
无需额外改动，只要调用方 dict 里带上 `raw_response` 键即可落库。

### 3. `insurance/ai_checker.py`（自动质检同步落库，保持口径一致）

`run_ai_check()` 组装质检流水 `log` 时新增：`"raw_response": extract.get("raw_response", "")`，
让自动触发的质检流水与手动质检一样保存原始返回值，未来「质检问题列表→详情」等入口也能复用。

### 4. `insurance/api.py`（手动质检接口：落库 + 回传前端）

- `ai_extract_record()`（`POST /api/insurance/ai-extract/<record_id>`，手动触发「本次」质检的接口）：
  - 写入 `ai_check_log` 的 `log` dict 新增 `"raw_response": extract.get("raw_response", "")`；
  - 返回给前端的 `data` 里新增 `"raw_response": extract.get("raw_response", "")`。
- `get_record_ai_check_detail()`（`GET /api/insurance/records/<record_id>/ai-check`，预览弹窗打开时
  拉「历史结果」用的接口）：`comparison` 字典里新增
  `"raw_response": last_extract_log.get("raw_response") or ""`，使「历史结果」模式（`fromHistory=true`）
  同样能看到当次质检落库的原始返回值；此前未落库的历史记录该字段为空。

### 5. `web/templates/insurance.html`（前端：按钮 + 弹窗）

- `previewAiCheck` 响应式对象新增字段 `rawResponse: ''`；`_fillPreviewAiCheck()`（本次结果/历史结果
  两条路径共用）新增 `previewAiCheck.rawResponse = d.raw_response || '';`；`resetPreviewAiCheck()`
  重置时一并清空，并顺带关闭原始返回弹窗。
- AI质检面板头部（「本次结果·模型·耗时」那一行，约第 5306-5324 行）新增「原始返回」按钮：
  - 有数据时可点击，打开弹窗；
  - `previewAiCheck.rawResponse` 为空（多为历史记录未落库该字段）时按钮置灰禁用，
    `title` 提示「无原始返回数据（历史记录未保存）」。
- 新增独立弹窗「API原始返回值」（约第 5465-5482 行，样式复用页面已有的 `aiCheckModal`/
  `aiCheckDetailModal` 居中弹窗风格，`z-index:1002`）：
  - 顶部显示模型名 + 复制按钮 + 关闭按钮；
  - 内容区用等宽字体 `<pre>` 展示，`white-space:pre-wrap` 支持长文本换行、内部滚动、可全选复制；
  - 新增计算属性 `aiRawResponseFormatted`：先尝试 `JSON.parse` 原始文本再 `JSON.stringify(obj, null, 2)`
    美化展示，解析失败（非合法 JSON/文本被截断等）则原样展示；
  - 复制逻辑 `copyAiRawResponse()` 复用页面已有的「写剪贴板失败则降级用 textarea+execCommand」模式
    （与既有的 `copyRawText()` 手法一致）。
- 新增的 `aiRawResponseModalVisible`/`aiRawResponseFormatted`/`aiRawResponseCopied`/
  `copyAiRawResponse` 已加入 `setup()` 的 `return {...}` 导出列表。

## 数据库变更

`ai_check_log` 表新增列 `raw_response LONGTEXT`（幂等迁移，首次访问相关接口时随
`init_insurance_tables → init_ai_tables` 自动 `ALTER TABLE ADD COLUMN`，无需手动执行 SQL）。
本地开发入口 `run_ocr.py` 已经调用 `init_insurance_tables`，无需额外同步。

## 交互说明

- 按钮位置：预览弹窗右侧「AI质检」面板顶部，「本次结果/历史结果·模型·耗时」那一行的最右侧，
  文案「原始返回」。
- 点击后弹出居中弹窗展示原始返回文本（JSON 自动美化，非 JSON 原样展示），可复制、可滚动。
- 兼容性：历史质检记录若是在本次改动之前生成的，`ai_check_log.raw_response` 为空，按钮自动置灰，
  不可点击，`title` 提示原因；不影响原有对比表格的展示与「应用AI值」等既有功能。

## 部署步骤

1. 上传 `insurance/ai_extractor.py`、`insurance/ai_db.py`、`insurance/ai_checker.py`、`insurance/api.py`、
   `web/templates/insurance.html` 到服务器对应目录（后端传到 `/home/wxbot/insurance/`，前端传到
   `/home/wxbot/web/static/insurance.html`）。
2. `kill -HUP` 平滑重载 gunicorn；`ai_check_log.raw_response` 新列会在应用重启后随
   `init_insurance_tables` 自动迁移，无需手动改表。
3. 以上部署动作需先征得用户明确同意后执行，本次仅完成本地代码修改。

# 追加：「质检问题列表」操作栏「查看原件」改为「预览」，复用台账预览弹窗+自动展开AI质检面板

## 需求说明

「质检问题列表」（AI质检 Tab）操作栏原来的「查看原件」按钮是直接 `window.open(cos_url)` 新开标签页看
PDF 原件。现在改成「预览」：不再单独开原件，而是复用台账记录列表里已有的「预览」弹窗（左边 PDF 预览、
右边 AI质检/识别对比面板），并且打开后自动切换到 AI质检 面板，直接展示该记录的历史质检对比结果——
这一步只读历史结果，**不重新调用大模型**（避免误触发额外的 API 费用）。

## 排查结论：功能已存在，只是没有复用

台账记录列表里点击行「AI质检」按钮时，走的是 `openRecordAiCheck(record)` 函数（`web/templates/
insurance.html` 第 9406 行）：内部调用 `previewRecord(record)` 打开预览弹窗、隐藏其它侧栏、展开
`previewShowAiCheck`，并在 `previewAiCheck.state === 'idle'` 时调用 `loadPreviewAiCheckHistory(record)`
—— 这条链路本来就是走 `GET /api/insurance/records/<record_id>/ai-check`（历史质检结果只读接口），
不会触发大模型调用。「质检问题列表」的每一行 `issue` 对象本身就带有 `id`（`insurance/ai_db.py` 的
`query_ai_check_issues()` 里 `SELECT r.id ...` 已经把 `insurance_records.id` 作为 `issue.id` 返回，
`resolveAiIssue()` 的「采纳AI值/保留原值」按钮本来就在用 `issue.id` 调 `/api/insurance/records/
${issue.id}/ai-check/resolve`），以及预览弹窗所需的 `cos_url`、`filename`。因此不需要改后端，
直接把「质检问题列表」的按钮指向已有的 `openRecordAiCheck(issue)` 即可完全复用。

## 代码变更（仅 `web/templates/insurance.html`）

- 「质检问题列表」操作栏按钮（原第 2319 行附近）：
  ```html
  <!-- 修改前 -->
  <button v-if="issue.cos_url" @click="openIssueFile(issue)" class="btn btn-outline" ...>查看原件</button>
  <!-- 修改后 -->
  <!-- 预览：复用台账「预览+AI质检」弹窗，打开后自动展开AI质检面板并加载历史质检结果（不重新调用大模型） -->
  <button v-if="issue.cos_url" @click="openRecordAiCheck(issue)" class="btn btn-outline" ...>预览</button>
  ```
- 删除了不再使用的 `openIssueFile(issue)` 函数（原第 10012-10015 行，`window.open(issue.cos_url)` 单独
  开原件的旧逻辑）及其在 `setup()` `return {...}` 里的导出，避免死代码。
- `openRecordAiCheck` 本身未改动（已在 `return {...}` 导出列表中，无需重复导出）。
- 「采纳AI值」「保留原值」按钮（`resolveAiIssue`）未改动。

## record 如何拿到、弹窗如何打开、AI质检面板如何自动展开

1. `aiIssues.list` 的每一项 `issue` 已经带有 `id`（=记录id）/`filename`/`cos_url`，满足
   `previewRecord(record)` 的前置条件（`record.cos_url && record.id`），无需额外查询单条记录接口。
2. `openRecordAiCheck(issue)` → `await previewRecord(issue)`：立即用 `issue` 的基本字段打开预览弹窗
   （`previewVisible.value = true`）并加载 PDF；随后异步请求 `GET /api/insurance/records/<id>` 补全
   完整详情（`parsed_fields`/`manual_fields`/`ai_fields` 等），覆盖 `previewAutoRecord.value`。
3. `previewRecord` 内部会先调用 `resetPreviewAiCheck()` 把 AI质检面板状态复位为 `idle`；
   `openRecordAiCheck` 紧接着把 `previewShowFields/previewShowRaw/previewShowRules/previewShowCompare`
   全部收起、`previewShowAiCheck.value = true`，即自动切到/展开 AI质检 面板。
4. 面板展开且状态为 `idle` 时，调用 `loadPreviewAiCheckHistory(previewAutoRecord.value)`，请求
   `GET /api/insurance/records/<record_id>/ai-check`（只读历史质检快照 + 实时列表值对比），填充
   `previewAiCheck`（含上一条改动新增的 `rawResponse` 原始返回值），状态置为 `done`，用户直接看到
   对比表格；全程不会触发 `POST /api/insurance/ai-extract/<record_id>`（重新调用大模型的接口）。

## 数据库变更

无（`query_ai_check_issues()` 已返回 `id`，未改动 SQL）。
