# 更新记录：修复时间排序下识别记录导出与列表顺序不一致

## 需求说明

用户反馈：列表按时间排序（如创建日期）时，导出的 Excel 顺序与列表不一致。

排查结论：识别记录导出（不勾"按车牌合并"）时，前端已按用户所选排序取数并做了"同车牌聚组 + 车内险种排序"的温和重排，但后端 `/api/insurance/export/excel` 的普通导出分支会**无条件**把传入数据按（车牌、险种）整体重排，导致时间排序被打乱、导出 Excel 变成按车牌字母序。此前修"导出跟随页面排序"时只改了合并导出分支（跟随 `_order` 传入顺序）和前端，普通导出分支的强制车牌排序漏改。

## 修复方案

在导出请求体新增 `preserve_order` 标志：

- **识别记录导出**（前端已排好序）传 `preserve_order: true` → 后端跳过按车牌重排，跟随传入顺序，与合并导出分支行为对齐，导出顺序与列表一致
- **手动上传结果导出**不传该标志 → 保留旧行为（按车牌+险种排序，使同车保单相邻），不受影响
- 老版本前端不传该标志 → 行为不变，兼容历史版本

## 数据库变更

无。

## 代码变更

### `insurance/api.py`

- `export_excel` 普通导出分支：`invoices.sort(key=(车牌, 险种))` 改为仅在请求体无 `preserve_order` 时执行

### `web/templates/insurance.html`

- `sendExportRequest()` 新增 `preserveOrder` 参数，透传为请求体 `preserve_order`
- `confirmExport()` 识别记录导出路径传 `preserveOrder=true`；手动上传路径不传（false）
- 新增 `batchExportPreserveOrder` ref：分批导出时暂存该标志，`executeBatchExport()` 透传，保证识别记录分批导出同样保持顺序

## 遗留提示（非本次修复范围）

- 若用户**未手动切换过**页面排序，导出取数用的是"导出列配置"的默认排序（`exportDefaultSort`/模板默认排序），列表用"页面列配置"的默认排序（`listDefaultSort`）；两处配置不同则源头顺序即不同。属产品设计，如需一致请在模板中将两处默认排序配成相同值。
- 不合并导出仍会做"同车牌聚组"（同车牌记录拉到首次出现位置、车内按险种排），为有意设计。
