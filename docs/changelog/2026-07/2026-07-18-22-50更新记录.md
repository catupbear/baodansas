# 2026-07-18 保单预览加载优化：COS 直连（免服务端中转）

## 需求说明

预览 PDF 加载慢。原因是预览走服务端代理接口：服务器先把整个 PDF 从 COS 全量下载到内存，才开始回传给浏览器，文件走了「COS → 服务器 → 浏览器」两段传输，首字节等待时间 = 完整下载时间。

本次改造为浏览器直连 COS 加载（预签名 URL），服务端不再中转文件；代理接口保留为兜底，并改为流式转发。

### 排查结论（背景）

- 当初做代理是因为直接打开 COS URL 会触发下载而非预览
- 根因：保单 PDF 上传时未设置 Content-Type，且 COS 对浏览器导航加载存在「强制下载」策略（响应带 `x-cos-force-download: true`，强制 `Content-Disposition: attachment`，预签名 URL 的 `response-content-disposition=inline` 覆盖参数也会被压掉）
- **该强制下载策略只对浏览器导航加载（iframe/地址栏）生效，对 fetch 字节流无效** —— 实测脚本探测拿不到该头、真实浏览器却会触发下载，因此方案上彻底绕开导航加载，不做服务端探测
- 桶原先未配置 CORS，本次已添加规则（直连 fetch 的前提）

### 最终方案：两端都用 fetch 字节流直连

| 端 | 加载方式 | 失败回退 |
|---|---|---|
| 桌面 iframe | fetch 直连 COS → 转 blob URL 给 iframe，原生 PDF 查看器照常渲染（blob 不受强制下载头影响） | fetch 失败自动回退代理接口 |
| 微信/移动 pdf.js | fetch 直连 COS → pdf.js 渲染 canvas | fetch 失败自动回退代理接口 |
| 图片 | `<img>` 直连（img 标签不受强制下载头影响） | — |

## COS 桶配置变更（已通过 SDK 执行）

桶 `ledger-1356055340`（ap-guangzhou）新增 CORS 规则 `wxbot-preview-direct`：
来源 `*`、方法 `GET/HEAD`、Expose Headers `Content-Length,ETag,Accept-Ranges,Content-Range`、缓存 600s。

「强制下载」开关无需改动（fetch 方案不受其影响）。

## 代码变更

### core/cos_storage.py

- 新增 `get_presigned_url_from_url()`：根据库中存储的 COS/CDN URL 反推 key，生成预签名直连 URL，支持 `response-content-type` / `response-content-disposition=inline` 响应头覆盖

### insurance/api.py

- 新增 `GET /api/insurance/records/<id>/preview-url`：返回预签名直连 URL（有效期 1 小时）
- `GET /api/insurance/records/<id>/preview` 代理接口改为**流式转发**（原来整文件读入内存后才开始响应），保留为直连失败的兜底路径
- 提取 `_PREVIEW_MIME_MAP` / `_preview_mimetype()` 公共映射

### web/templates/insurance.html

- `previewRecord()`：先调 `/preview-url` 获取直连 URL；桌面 PDF 走 `loadIframePdfBlob()`（fetch → blob URL → iframe），微信/移动走 pdf.js，图片直连 img
- 新增 `loadIframePdfBlob()`：带加载序号防竞态（中途关闭/切换记录时丢弃迟到结果），失败回退代理
- `renderPdfCanvas()`：支持 `fallbackUrl`，直连 fetch 失败自动回退代理接口
- 关闭预览时 revoke blob URL 释放内存
- 预览弹窗改为先打开再异步解析 URL，避免多一次等待

## 兼容性

- 老版本前端不受影响：`/preview` 代理接口保留且行为不变（仅内部改流式，响应更快）
- 任何直连失败场景（签名失败、CORS 异常、网络问题）自动回退代理，与原行为一致
