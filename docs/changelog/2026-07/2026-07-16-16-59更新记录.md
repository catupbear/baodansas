# 2026-07-16 16:59 更新记录 —— 群信息统一同步（wecom_groups + 独立定时任务）

## 需求说明

系统内群名来源分散在 4 处（`contacts_cache` 永久缓存、`insurance_records.room_name` 入库固化值、监控配置里的 `{id,name}` 快照、前端现场补解析），导致同一个群各页面显示不一致、群改名不更新、解析失败后前端裸显 roomid。

本次按《群信息统一同步方案》（docs/review/群信息统一同步方案.html）实施一、二期：

1. **一期**：新建统一群信息表 `wecom_groups` + 独立定时同步任务 `task_group_sync.py`（参考 wuhuApi/task.py 形态，独立进程，与 web 服务解耦）；
2. **二期**：全系统 4 处群名读取切换为共用 `wecom_groups`。

三期（客户群列表全量发现）暂未实施。

## 数据库变更

新表 `wecom_groups`（web 服务和同步任务启动时都会自动建表，无需手动执行 SQL）：

| 字段 | 说明 |
|------|------|
| roomid (PK) | 群ID |
| corpid | 解析成功的企业 |
| name | 群名（权威值） |
| owner / member_count / group_type | 群主 / 成员数 / internal·external |
| sync_status | ok / failed / unresolvable / pending |
| fail_count | 连续失败次数（≥5 退避为每天试 1 次） |
| first_seen_at / name_updated_at / last_attempt_at / last_synced_at | 各时间戳 |

写入规则：拉取失败**不覆盖旧群名**；群解散（errcode 40050）保留最后已知群名并标记 unresolvable；群名变化记 `name_updated_at`。

## 部署步骤

1. 上传文件到服务器：
   - `storage/group_db.py`（新增）
   - `task_group_sync.py`（新增，项目根目录）
   - `main.py`、`insurance/api.py`、`insurance/db.py`、`insurance/handler.py`

3. 启动独立同步进程：
   ```bash
   cd /home/wxbot
   nohup python3 task_group_sync.py >> logs/group_sync.log 2>&1 &
   ```
   （建议后续配 systemd/supervisor 托管，与 wuhuApi task.py 同款运维方式）
4. 验证：
   - `tail -f logs/group_sync.log`：出现「群同步任务启动」→ 首轮全量「全量刷新完成: 共 N 个群, 成功 …」；
   - `SELECT sync_status, COUNT(*) FROM wecom_groups GROUP BY 1;`：ok 占比应 > 90%；
   - 前端台账「群名」下拉与监控配置页：原来显示 `wrmjPuGQAA...` 的群变为真实群名（企微可解析的）。
