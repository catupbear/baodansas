# 车牌回填匹配归一化 + 企业未配置补充模板群提醒 + phone类型不做过滤

## 需求说明

1. **车牌匹配兼容带`-`/不带`-`**：群内补充按车牌回填时，库里的"车牌号"可能是
   OCR 识别或手动修改后的值（如 `粤E-R705I`、小写、带空格），原来是精确匹配，
   格式稍有差异就命中0条。改为匹配时两侧归一化（去半/全角连字符、空格、间隔点，
   转大写）。
2. **手动修改过的记录也能匹配**：前端手动修改字段时值会同步写回
   `parsed_fields["车牌号"]`（`insurance/api.py` 字段编辑端点），归一化匹配后
   手动改成任意常见写法均可命中。
3. **企业未配置补充模板提醒**：客户已在群里发补充信息文本、且回填成功，但该群
   所属企业从未在「字段配置 → 群内补充」保存过关键词模板（走的默认写死规则）时，
   机器人在群内发提醒并 @技术客服（午虎保单台账系统），推动尽快配置专属模板。
4. **phone 类型不做合法性过滤**：可配置引擎中 value_type=phone 原来只认合法
   11 位手机号，客户发分机号/座机/截断号码（如"电话：15778"）会被跳过。改为
   关键词后跟的数字原样采集（3~20 位，允许中间夹 `-` 或空格分隔）。
5. **车牌不做格式校验，只限最大位数**：原来车牌必须是"省简称+字母+4~6位"标准
   格式（如"粤111111"全数字就被当普通聊天忽略、无任何提醒）。改为：标准格式
   匹配不到时，退回"车牌"关键词后的值采集，不做格式校验，仅要求含字母/数字且
   归一化（去`-`/空格后）不超过 8 位（新能源车牌上限）。格式错误的车牌照常按
   车牌匹配记录，命中0条自然走"未录入"提醒（文案已引导核对车牌），无需单独的
   格式错误文案。超过 8 位视为非车牌、忽略。
6. **日志用词**：「政策回填」统一改为「群内回填」。
7. **防自触发循环（配置层，已即时生效）**：机器人通知文案含"车牌：xxx/业务经理"
   等关键词，发进群后会被会话存档拉回再解析，可能形成通知死循环。已将通知文案
   特征词加入全局跳过黑名单 `group_fill_skip_keywords`：新增「补充信息未录入」
   「群内补充提醒」（原有「群公告」保留）。⚠️ 自定义通知模板时必须保留这些特征
   词之一，否则失去防循环保护。

## 提醒文案（方案B，默认模板）

> @技术客服（午虎保单台账系统）
> ⚠️ 群内补充提醒：车牌 {plate} 的补充信息已收到，但贵司暂未配置补充信息模板，部分内容可能未生效。
> 技术客服将尽快为贵司完成配置，请留意群内通知。

- `{plate}` 动态替换为解析到的车牌
- 只 @技术客服，不 @发送人（发送人无需操作，减少打扰）
- **同一群每天最多提醒一次**（内存节流，进程重启后重置）
- 与「补充未录入通知」互斥：命中0条走未录入通知，命中>0且未配置模板才走本提醒

## 数据库变更

无表结构变更。新增 `insurance_config` 配置键 `quote_fill_template_notify`：

```json
{
  "enabled": true,
  "robot_id": "",
  "tech_support_name": "技术客服（午虎保单台账系统）",
  "template": ""
}
```

- `enabled`：开关，**默认关闭**
- `robot_id`：可选，缺省复用 `flowbot_fail_notify` 的机器人 ID
- 其余同 `quote_fill_miss_notify`
