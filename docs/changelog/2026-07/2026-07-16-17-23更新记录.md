# 2026-07-16 17:23 更新记录 —— 群同步修复：排序规则冲突 + 列表发现限定午虎科技

## 需求说明

群同步任务上线后发现两个问题：

1. **排序规则冲突**：`wecom_groups` 按 MySQL 8 默认排序规则建成了 `utf8mb4_0900_ai_ci`，与 `messages`（`utf8mb4_unicode_ci`）JOIN 时报 `Illegal mix of collations (1267)`，增量发现/全量刷新全部失败；
2. **列表发现范围过大**：客户群列表发现把车物家的 1338 个客户群全部拉了进来，实际只需要午虎科技的群。

## 数据库变更

无需手动执行 SQL——`init_group_table` 会自动完成：

- 建表时动态读取 `messages` 表的排序规则并对齐（不再依赖服务器默认值）；
- 已存在的旧表若排序规则不一致，自动 `ALTER TABLE ... CONVERT TO`（表小，秒级）。

## 代码变更

### `/Users/take/Downloads/yun/web/wxbot/storage/group_db.py`

- `init_group_table`：建表排序规则与 `messages` 对齐 + 旧表自动转换（修复 1267 错误）；
- 新增 `cleanup_pending_external(db, allowed_corpids)`：清理白名单外企业由列表发现误插入的待解析群（`pending + external` 组合只可能来自列表发现，messages 增量发现的群不受影响）。

### `/Users/take/Downloads/yun/web/wxbot/task_group_sync.py`

- 新增配置 `group_sync.list_corp_names`（企业名白名单）：**不配置默认只跑「午虎科技」**，配 `[]` 表示全部企业；
- `run_list_discovery` 按白名单过滤企业，并在每轮开始时自动清理白名单外的待解析群——重启后车物家那 1338 条 pending 记录会被自动删除。

## 部署步骤

1. 停掉当前同步进程：`pkill -f task_group_sync.py`
2. 上传 `storage/group_db.py`、`task_group_sync.py`
3. 重启同步进程：
   ```bash
   cd /home/wxbot && nohup python3 task_group_sync.py >> logs/group_sync.log 2>&1 &
   ```
4. 验证日志依次出现：
   - `wecom_groups 排序规则 utf8mb4_0900_ai_ci 与 messages(utf8mb4_unicode_ci) 不一致，自动转换`
   - `已清理白名单外企业的待解析群 1338 个`
   - `[午虎科技] 客户群列表发现: 共 65 个群`
   - `全量刷新完成: ...`（不再报 1267）
5. web 服务无需改动（但建议也重启一次，让 `init_group_table` 的新逻辑生效——两边都会自动转换，先启动哪个都行）。
