# 2026-05-17 补扫历史保单功能

## 需求说明

用户配置新的监控规则后，历史消息中的 PDF 不会被自动匹配识别。需要提供一个手动触发的方式，让用户可以对历史消息重新进行保单匹配。

## 代码变更

### 1. `core/fetcher.py` — 扩展 `rescan_missed_insurance` 方法

- 新增参数：`config_ids`（指定监控配置）、`room_ids`（指定群）、`force`（强制重新识别）
- 返回值从 None 改为 int（入队数量）
- force 模式下不排除已有 insurance_records 记录的消息

### 2. `insurance/api.py` — 新增 `POST /api/insurance/rescan` 端点

| 参数 | 类型 | 说明 |
|------|------|------|
| lookback_days | int | 回溯天数（1-365），默认 5 |
| config_ids | list[int] | 可选，指定监控配置 ID |
| room_ids | list[str] | 可选，指定群 ID |
| force | bool | 是否强制重新识别，默认 false |

### 3. `web/templates/index.html` — 消息监控页面增加「补扫历史保单」按钮

- 顶部工具栏增加按钮
- 弹窗支持选择：回溯天数、监控配置范围、是否强制重新识别
- 调用 API 后显示入队数量

## 数据库变更

无

## 部署步骤

1. 更新代码并重启服务即可，无需数据库迁移
