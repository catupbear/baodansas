# 2026-06-02 18:00 更新记录

## 需求说明

兼容平安商业险保费提取。某平安机动车商业保险电子保单，保险费合计实际为
`RMB2965.86元`，但系统提取成了 `65.86`。

## 问题根因

`insurance/policy_parser.py` 的 `_extract_premium` 在小写金额提取成功后，会做一次
「大写金额交叉验证」：在「保险费合计」标签附近查找大写中文金额，若与小写金额差异
>1% 则优先采用大写金额（用于纠正个别 OCR 数字错误）。

该平安保单中，pdfplumber 因右单元格文本换行，把大写金额拆成了两段，且行标签
「保险费合计」被插在两段中间：

```
RMB2965.86元（不含税保费:2797.98元，税额:167.88元）（大写）人民币贰仟玖
保险费合计
佰陆拾伍元捌角陆分
```

交叉验证的间隔字符集未排除换行符，于是从「保险费合计」向下跨行匹配到后半段残缺
金额「佰陆拾伍元捌角陆分」= 65.86，与正确的小写 2965.86 差异 97.8%，触发覆盖，
最终把保费写成了 65.86。

## 代码变更

`insurance/policy_parser.py` — `_extract_premium` 大写交叉验证增加两道防御：

1. 间隔字符集排除换行符 `\n`，使大写金额必须与标签处于同一行（连续），不再跨越
   被换行拆分的残缺片段。
2. 防御性校验：若捕获到的大写金额以「佰/仟/万/亿」等大单位开头（前面无数字），
   说明是被换行截断的残缺片段（完整金额必以数字或「拾」开头），跳过覆盖。
