# 修复：「交强到期时间」日期格式配置不显示 + 配置不生效

## 需求说明

1. 字段配置页面「日期格式」标签页中只列出了 签单日期、起保日期、终保日期、创建时间、识别时间，
   缺少「交强到期时间」字段，用户无法为该字段单独配置显示格式。
2. 即使补上配置项，列表页/导出中「交强到期时间」仍按「终保日期」的格式显示，
   用户自己为「交强到期时间」选择的格式不生效。

## 问题原因

### 问题 1：前端缺字段

前端 `web/templates/field_config.html` 中日期格式列表 `dateFields` 为硬编码数组，
新增字段「交强到期时间」时未同步加入该列表。

### 问题 2：格式不生效（核心）

「交强到期时间」并非 OCR 直接提取的字段，而是在列表/导出时**动态注入**：
取同车牌交强险记录的「终保日期」填入。原代码的注入时机在 `apply_user_config_to_fields`
（日期格式化）**之后**，且：

- 列表路径：注入用的「终保日期」此时已被格式化成「终保日期」自己的格式
  （如 `MM月DD日` → "06月25日"），**年份已丢失**，无法再按「交强到期时间」的格式还原；
- 导出路径：注入的是原始终保日期，但注入后未经过任何格式化。

两条路径都导致「交强到期时间」无法按其自身配置的格式显示。

## 代码变更

### `web/templates/field_config.html`

- 在 `dateFields` 列表中「终保日期」后新增 `{ name: '交强到期时间', format: 'YYYY-MM-DD' }`，
  作为纯日期字段（使用 `dateFormats`，不含时分）。

### `insurance/api.py`

- 顶部从 `insurance.field_config_db` 额外导入 `_format_date`，并新增 `import re`。
- 新增 `_norm_plate()` 车牌归一化辅助函数（去连字符/空格，仅用于匹配，不改显示值）。
- **车牌匹配 bug 修复（核心）**：数据库车牌无连字符（如 `粤BCM3220`），但前端对平安等
  保单会格式化为 `粤B-CM3220`。构建映射在格式化前（原始车牌）、注入在格式化后（带连字符车牌），
  导致 key 不匹配 → 交强到期时间为空。现统一用 `_norm_plate()` 归一化映射 key、数据库查询入参
  及注入查询 key。
- **格式不统一修复**：构建同页映射时只采用「含 4 位年份」的终保日期；前端 `config_applied=True`
  传来的终保日期可能已被格式化成无年份（如 `MM月DD日`），此类留给数据库兜底查询（`end_date`
  含年份），避免格式化时无法解析年份导致部分记录格式不统一。
- **导出以数据库原始数据为准**：导出接口的 `invoices` 来自前端请求体，`config_applied=True` 时
  其中车牌/终保日期可能已被规则转换（车牌加连字符、日期格式化丢年份），不可作为匹配依据。
  改为只取前端车牌做归一化 key，交强到期时间一律走 `insurance_policy_fields.end_date`（原始值）
  查询。列表接口本就读取数据库原始 `display_fields`（`apply_mapping` 仅映射键名、不改值）
  + `policy_fields` 兜底，匹配用的同样是原始数据。

> 说明：规则转换（公司/险种简称、日期格式化、车牌连字符）仅在请求时由
> `apply_user_config_to_fields` 临时应用，**不写回数据库**。原始数据保存在 `parsed_fields`（JSON）
> 与 `insurance_policy_fields` 表中，匹配交强到期时间时均以原始数据为准。
- **列表接口**：在 `apply_user_config_to_fields`（格式化）**之前**，用「原始」终保日期
  构建 `车牌 → 交强险终保日期` 映射；注入时按「交强到期时间」自身配置的格式调用
  `_format_date` 格式化。手动填写过的值（已在格式化阶段处理）不覆盖。
- **导出接口**：将原始终保日期映射 + 格式提取上移到合并/不合并分支之前，提取为公共
  `_inject_compulsory_end()` 辅助函数；注入时按配置格式格式化。同时让**合并导出**也注入
  「交强到期时间」（此前合并模式下该列为空）。

后端通用日期格式化逻辑（`field_config_db._format_date` / `apply_user_config_to_fields`）
本身无需改动，仅修正了注入时机与对注入值的单独格式化。

## 数据库变更

无。

## 部署步骤

重启服务并刷新前端页面即可生效。用户需在「日期格式」中为「交强到期时间」选择期望格式。
