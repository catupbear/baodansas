# 兼容阳光保险商业险被保险人提取

## 需求说明

阳光财产保险（商业险电子保单）的「被保险人」无法正常提取，前端显示为「—」。

示例：被保险人应为 `深圳市民丰胶粘制品有限公司`，实际提取为空。

## 根因定位

阳光保单的「被保险人」是**合并单元格**（纵向跨「名称」「地址」两行），
pdfplumber 把合并标签落在了「地址」那一行，导致真正的被保险人名称所在的
「名称 XXX 证件号码 YYY」行没有被「被保险人」标签关联。提取到的文本布局：

```
投保人 薛德民
名称 深圳市民丰胶粘制品有限公司 证件号码 91440300326351425P   ← 被保险人名称在这行
被保险人 广东省深圳市宝安区西乡街道...机房整套A              ← 被保险人标签 + 地址值
地址 联系方式 136****7771
```

原通用提取逻辑：
- 「被保险人」标签后跟的是地址（被 `_is_valid_person` 判为非人名而丢弃）
- 「被保险人」又不是独立成行，命不中「被保险人独立行 → 向附近找名称」的分支
- 因此「名称」行始终没被关联到被保险人 → 提取为空

## 修复方案

新增阳光专用提取 `_extract_insured_yangguang()`：定位「被保险人」标签行，
**向上回溯最近的「名称 XXX 证件号码」行**取其中的名称作为被保险人。
仅当 `company_short == "阳光"` 时启用，不影响其它保司。

## 数据库变更

无。

## 代码变更

- `insurance/policy_parser.py`
  - 新增 `_extract_insured_yangguang()` 函数
  - `_extract_insured()` 在通用提取前新增阳光分支调用

## 兼容性

- 仅阳光保司走新逻辑；人保、平安、太平洋等已验证被保险人提取不受影响
- 阳光驾乘险/驾意险：其「车上人员描述」「与投保人关系本人」等场景由更靠前的
  通用分支先处理，新分支只在标准「被保险人 + 名称/证件号码」布局下生效
- 历史已入库记录不会自动更正，需要时由前端「识别有误？点击修改」手动修正或重新识别

## 部署步骤

直接更新代码重启服务即可，无需迁移。
