# 修复车牌号被错误识别（粤B50LH0 → 粤B50LHO）

## 需求说明

保单 PDF 中车牌号 `粤B50LH0`（末位数字 0）被识别成 `粤B50LHO`（末位字母 O）。

## 根因定位（已核实）

完整链路如下：

1. pdfplumber 成功提取文本层（7355 字），文本中车牌是**正确**的 `粤B50LH0`。
2. 但该 PDF 文本含 282 个 Unicode 非字符（U+FFFE/U+FFFF，字体编码异常的伴生产物）。
3. 原降级逻辑：含非字符时，只有命中保司白名单（仅 `太平洋`）才「清理后继续用 pdfplumber」，
   其余一律降级 OCR。人保（PICC）不在白名单 → **被错误降级到 OCR**。
4. OCR 引擎（火山/百度）把数字 `0` 误识成字母 `O`，最终入库 `粤B50LHO`。

实际日志：
```
pdfplumber 提取文本含Unicode非字符（U+FFFE/U+FFFF），字体编码异常，降级 OCR（count=282）
火山引擎OCR第1/8页识别成功 ...
```

**根因 = 误降级**：pdfplumber 文本清理掉非字符后完全可用（confidence 1.0、车牌正确），
不该降级 OCR。OCR 只是误降级后的二次伤害。

## 修复方案

### 1. 主修复 —— 消除误降级（`insurance/handler.py`）

把「按保司白名单」判断改为「按内容质量」判断：含非字符时先清理非字符，
再用 `parse_policy_text` 评估清理后文本的 confidence；
- confidence ≥ 0.4 且 category ≠「其他」→ 保留 pdfplumber 文本（比 OCR 更准确，不降级）
- 否则才降级 OCR

这样对所有保司通用，无需再逐家维护白名单，从源头避免误降级。

### 2. 兜底修复 —— 车牌序号归一化（`insurance/policy_parser.py`）

针对**确实需要走 OCR** 的扫描件，增加解析层兜底。依据国标 **GA 36-2018**：
车牌序号（第 2 位发牌机关代号之后）只用数字 0-9 和字母 A-Z，且**不含字母 I、O**
（标准本就是为避免与 0、1 混淆）。因此序号出现的 O/I 必为 OCR 误识，归一化为 0/1：

- 第 0 位（省份汉字「粤」）、第 1 位（发牌机关代号「B」）保持不变
- 第 2 位起（序号）：`O → 0`，`I → 1`
- 仅对「省份汉字 + 字母」开头的标准车牌生效；「新车」等占位值不处理

## 数据库变更

无。

## 代码变更

- `insurance/handler.py`
  - 非字符降级判断：白名单 → 内容质量（清理后 confidence 评估），消除人保等保司的误降级
- `insurance/policy_parser.py`
  - 新增 `_normalize_plate()`，归一化车牌序号 O→0 / I→1
  - `_extract_vehicle_info()` 车牌提取后调用归一化（排除「新车」占位值）

## 兼容性

- 历史已入库的错误车牌不会自动更正，需要时由前端「识别有误？点击修改」手动修正，或重新识别
- 原白名单保司（太平洋）行为不变：其文本同样通过内容质量检查，继续保留 pdfplumber

## 部署步骤

直接更新代码重启服务即可，无需迁移。
