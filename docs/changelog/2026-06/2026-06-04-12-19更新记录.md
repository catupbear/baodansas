# 保单识别 - 自定义时间筛选支持选到具体时间

## 需求说明

保单识别记录页的「日期筛选」中，选择「自定义」区间时，原本只能选到日期（年月日）。
本次新增：当筛选类型为 **创建日期 / 识别日期** 时，自定义区间可以精确选择到具体时间（时:分）。

> 说明：签单日期 / 起保日期 / 终保日期 在数据库中为 DATE 类型，本身不含时间，
> 因此这三类仍只支持选到天，避免给用户造成"可选时间但实际无效"的误导。

## 数据库变更

无。`created_at` / `updated_at` 本就是 TIMESTAMP 类型，可直接按 `YYYY-MM-DD HH:MM` 比较。

## 代码变更

仅前端 `web/templates/insurance.html`：

1. **自定义区间输入框**：根据日期类型动态切换控件类型
   - 创建/识别日期 → `datetime-local`（可选到时分）
   - 保单日期（签单/起保/终保）→ `date`（仅到天）

2. **新增计算属性 `dateTypeSupportsTime`**：判断当前日期类型是否为 TIMESTAMP（`created_at` / `updated_at`），用于上述控件切换；并在 setup 的 return 中导出。

   **交互优化**：新增 `openNativePicker(e)`，给自定义区间输入框绑定 `@click`，点击输入框任意位置（含前面的"年/月/日"文本区）即调用原生 `showPicker()` 弹出选择器，不必再点右侧小图标；不支持 `showPicker` 的浏览器自动降级为原有行为。

3. **`_appendDateParams` 参数构建**：
   - 时间戳类型：将 `datetime-local` 的取值 `YYYY-MM-DDTHH:MM` 归一化为 MySQL 可识别的 `YYYY-MM-DD HH:MM`（替换 `T` 为空格）。
   - DATE 类型：统一截取日期部分 `slice(0,10)`，防止切换日期类型时残留带时间的值污染 DATE 列查询。

筛选区间语义保持不变：`[start, end)`（开始包含、结束不含），与既有快捷按钮一致。

## 部署步骤

纯前端模板改动，重启服务（或刷新页面）即可生效：

```bash
python main.py
```
