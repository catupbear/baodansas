# 身份证号提取限制区域到「保单正文」，根治条款附录注册编号误识别

## 需求说明

紫金驾意险（及同类「按座位数承保、被保险人无个人身份证」的保单）被保险人身份证号码仍被误提取为 `373252202303073814`。

该误值来自保单后部「保险条款/释义」附录中的「注册编号：C00013732522023030738143」——其内嵌的 18 位数字串恰好符合身份证格式（373252 + 2023-03-07 + 381 + 4）。

上一版虽已给兜底加数字边界，但身份证号本应只存在于「保单正文」，条款附录中的任何长数字串都不应参与识别。因此采用**限制提取区域**的方式从根本上规避（用户建议方向）。

## 数据库变更

无。

## 代码变更

`insurance/policy_parser.py` — `_extract_id_numbers()` 开头新增「正文边界截断」：

```python
# "注册编号"仅出现在条款附录标题区，正文不含，故以其首次出现处作为正文边界
_m_zce = re.search(r'注册编号', text)
if _m_zce and _m_zce.start() > 50:
    text = text[:_m_zce.start()]
_m_zce2 = re.search(r'注册编号', text_merged)
if _m_zce2 and _m_zce2.start() > 50:
    text_merged = text_merged[:_m_zce2.start()]
```

即：身份证号的所有提取逻辑只在「注册编号」之前的正文区域执行，彻底排除条款附录干扰。

## 兼容性说明

- 「注册编号」仅出现在条款附录标题区，保单正文（投保人/被保险人/车辆信息等）均在其之前，截断不会丢失正文中的身份证号。
- 加 `start() > 50` 守卫，避免极端情况下文首误截断。
- 无「注册编号」的保单（如部分交强险/发票）`_m_zce` 为空，保持全文提取，行为不变。
- 与上一版「脱敏还原」「数字边界」叠加，多重保险。

## 部署步骤

无数据库/配置变更，**重启服务**即可生效（线上需重启加载新代码）。
