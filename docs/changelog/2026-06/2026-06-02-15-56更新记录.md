# 紫金财产保险交强险保费提取错误修复

## 需求说明

紫金财产保险股份有限公司的交强险电子保单，保费合计提取错误：实际应为 **665**（陆佰陆拾伍元整），但系统错误提取为 **150**（车船税金额）。

## 问题根因

该保单 OCR 文本布局特殊：

```
陆佰陆拾伍元整 665.000.00.00          ← 保费大写在标签【上一行】
保险费合计（人民币大写）： （¥： 元）其中救助基金（ %） ¥： 元
...（中间隔着保险期间、纳税人信息等 100+ 字）...
壹佰伍拾元整 150.00                    ← 车船税大写（150）
合计（人民币大写）： （¥： 元）
```

提取流程实际分两步：

1. 「紫金格式2」分支正确读取标签上一行，提取出 `665.00`。
2. 但随后的「大写金额交叉验证」逻辑（`_extract_premium`）使用了**无长度上限**的正则
   `保险?费合计[^壹贰...]*?(大写金额)`，从标签**向后**搜索大写金额。由于保费大写在标签上方、
   标签后方最近的大写金额是 177 字之外车船税区域的「壹佰伍拾元整」(150)，
   交叉验证误将正确的 665 覆盖为 150。

## 代码变更

- `insurance/policy_parser.py` — `_extract_premium()` 大写交叉验证正则

  将无上限的 `[^壹贰...]*?` 改为限制搜索范围 `[^壹贰...]{0,40}?`，
  使交叉验证只在「保险费合计」标签后 40 字内寻找配套大写金额，
  避免跨段落误匹配到车船税区域的大写金额。

  - 合法场景（大写紧跟标签，如「保险费合计（人民币大写）：壹仟壹佰元整」）不受影响，
    仍可正常纠错（小写 OCR 错误时优先采信大写）。
  - 紫金交强险场景：标签后 40 字内无大写金额，交叉验证跳过，
    保留「紫金格式2」已正确提取的 665。

## 验证结果

| 场景 | 期望 | 修复后 |
|------|------|--------|
| 紫金交强险保费 | 665 | ✅ 665.00 |
| 紫金交强险车船税 | 150 | ✅ 150.00 |
| 大写纠错（小写1000/大写1100） | 1100 | ✅ 1100.00 |
| 大写一致（300） | 300 | ✅ 300.00 |
