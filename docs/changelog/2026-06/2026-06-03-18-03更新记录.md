# 兼容紫金交强险被保险人身份证号码（脱敏还原）

## 需求说明

紫金财产保险交强险（机动车交通事故责任强制保险）电子保单，被保险人身份证号码提取错误。

原因：
1. 保单正文中被保险人身份证号码被**脱敏**显示（如 `44148119910714****`，末 4 位打码），无法直接提取完整号码。
2. 完整号码出现在文档下方「纳税人识别号」处（`441481199107144834`），但与最近的「被保险人」锚点距离过远（中间隔着责任限额、保险费、保险期间等大量内容），原 200 字内兜底无法命中。
3. 原兜底无数字边界约束，反而命中了条款「注册编号：C0001**373252**2023030738143」中嵌套的伪身份证 `373252202303073814`，导致提取错误。

## 数据库变更

无。

## 代码变更

`insurance/policy_parser.py` — `_extract_id_numbers()` 新增「脱敏还原」逻辑（置于兜底之前）：

```python
# 交强险脱敏还原：被保险人身份证号码常被脱敏（如 44148119910714****），
# 但文档其它位置（如"纳税人识别号"）含完整号码，按脱敏前缀在全文还原完整号码。
if "被保险人身份证号码" not in fields:
    m_mask = re.search(r'(\d{12,16})\*{2,}', text)
    if m_mask:
        prefix = m_mask.group(1)
        m_full = re.search(r'(?<!\d)' + re.escape(prefix) + r'\d{1,5}[\dXx](?!\d)', text)
        if m_full and re.fullmatch(_ID_PATTERN, m_full.group(0)):
            fields["被保险人身份证号码"] = m_full.group(0)
```

配合上一版已加的兜底数字边界 `(?<!\d)...(?!\d)`，注册编号等长数字串中的伪身份证不再误命中。

## 兼容性说明

- 脱敏还原仅在已有特定模式未提取到时触发（`if ... not in fields`），不影响已能正确提取完整号码的保单。
- 触发条件严格：需同时存在「12~16 位数字 + 连续打码符」的脱敏串，且按前缀还原出的完整号码必须通过 `_ID_PATTERN`（18 位、合法出生日期）校验，误报概率极低。
- 无脱敏的保单（如驾意险）`m_mask` 为空，逻辑跳过，行为不变。

## 部署步骤

无数据库/配置变更，重启服务即可生效。
