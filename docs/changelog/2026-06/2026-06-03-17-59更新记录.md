# 兼容紫金财产保险「驾乘人员人身意外伤害保险」身份证号提取

## 需求说明

紫金财产保险（ZKING）驾乘人员人身意外伤害保险（驾意险）电子保单存在两个身份证号提取问题：

1. **投保人身份证号码漏提取**（前端显示「—」）
   - 该保单投保人信息区块标题为「投保人**基本**信息」，且 OCR 将「投保人名称：」拆行为：
     ```
     投保人名
     钟浩明
     称：
     证件类型：身份证 证件号码：441481199107144834
     ```
   - 原投保人兜底模式为 `投保人(?:信息|姓名)...证件号码`，无法匹配「投保人基本信息」，导致漏提取。
   - 应提取 `441481199107144834`。

2. **被保险人身份证号码误提取**
   - 该险种被保险人为「驾驶或乘坐车辆的人员，人数以核定座位数为限」，**本无具体身份证号**。
   - 但被保险人兜底模式 `被保险人[\s\S]{0,200}?<身份证>` 命中了条款「注册编号：C0001**373231**2023030738063」中嵌套的数字串，误识别为身份证号 `373231202303073806`。
   - 应为空。

## 数据库变更

无。

## 代码变更

`insurance/policy_parser.py` — `_extract_id_numbers()`：

1. 投保人信息块模式兼容「基本」二字：
   ```python
   # 原：投保人(?:信息|姓名)...
   r'投保人(?:基本)?(?:信息|姓名)[：:\s]*[\s\S]{0,200}?证件号码[：:\s]*' + _ID_PATTERN
   ```
2. 被保险人兜底模式加数字边界，避免命中长数字串中嵌套的伪身份证：
   ```python
   # 原：被保险人[\s\S]{0,200}?<身份证>
   r'被保险人[\s\S]{0,200}?(?<!\d)' + _ID_PATTERN + r'(?!\d)'
   ```

## 兼容性说明

- 投保人模式仅新增可选的「基本」二字，原「投保人信息/投保人姓名」格式完全兼容。
- 被保险人边界锚 `(?<!\d)...(?!\d)` 只排除被其它数字包裹的伪身份证（如注册编号），真实 18 位身份证（前有标签、后接空白/标点）不受影响，对历史保单无回归。

## 部署步骤

无数据库/配置变更，重启服务即可生效。
