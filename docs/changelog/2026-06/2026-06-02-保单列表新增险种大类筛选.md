# 功能：保单列表新增「险种」大类筛选

## 需求说明

保单识别列表主筛选栏新增「险种」下拉筛选，支持按 **商业险 / 交强险 / 驾意险 / 非车险**
四个大类筛选记录，服务端过滤、跨分页生效，并同步影响状态 Tab 计数与导出。

## 设计要点

险种大类由 `get_policy_type_code()` 按关键词归类（驾意险/非车险为兜底类，无法用单一
`LIKE` 精确匹配），而数据库 `insurance_policy_fields.policy_type` 存的是原始险种全称
（如「机动车商业保险」「平安车主尊享保障」）。

为保证筛选结果与列表展示的归类**完全一致**，采用「分类→IN 列表」方案：
取库中 distinct 的原始险种全称，逐一用 `get_policy_type_code()` 归类，取属于所选大类的
全称集合，再以 `pf.policy_type IN (...)` 过滤，不破坏分页。比较使用稳定的 `type_code`
（commercial/compulsory/accident/non_vehicle），避免 label「驾乘/意外险」与前端「驾意险」
用词差异导致匹配失败。

实测当前数据分类计数：商业险 1364 / 交强险 1251 / 驾意险 1097 / 非车险 27，与列表归类一致。

## 代码变更

### `insurance/db.py`

- 新增 `_policy_types_for_category(db, category)`：将大类中文映射为 `type_code`，
  取库中属于该类的原始险种全称列表（仅在启用险种筛选时执行 distinct 查询）。
- `query_insurance_records()` 新增 `policy_type` 参数，加入 `pf.policy_type IN (...)` 条件
  （无匹配险种时返回空）。
- `get_insurance_stats()` 同步支持 `policy_type`（计入 `need_join` 触发条件 + IN 过滤），
  使 Tab 计数与筛选一致。

### `insurance/api.py`

- `list_records` 读取 `policy_type` 请求参数并传入查询。
- `get_stats` 过滤参数白名单新增 `policy_type`。

### `web/templates/insurance.html`

- 主筛选栏「保司」旁新增「险种」下拉（固定四个大类选项）。
- 新增 `recordPolicyTypeFilter` ref；在 `loadRecords` / `buildStatsFilterParams`（Tab 计数）
  / `collectRecordsExportData`（导出）/ `collectBatchDownloadIds` / `batchReocrSync`
  五处请求构造中带上 `policy_type` 参数。
- `clearAllFilters()` 一并重置 `recordCompanyFilter` 与 `recordPolicyTypeFilter`
  （此前「清空所有筛选」未清空这两个独立 ref，顺带修复）。

## 数据库变更

无（复用既有 `insurance_policy_fields.policy_type` 列）。

## 部署步骤

重启服务并刷新页面即可。

## 备注

`_policy_types_for_category` 的 `SELECT DISTINCT policy_type` 为全表扫描（`policy_type`
无索引），distinct 基数很小（约数十种）、且仅在启用险种筛选时触发，当前数据量下开销可忽略；
若后续表体量极大可加进程内缓存优化。
