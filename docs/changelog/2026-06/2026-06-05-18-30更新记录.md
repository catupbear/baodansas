# 2026-06-05 18:30 更新记录

## 需求说明

线上日志出现保单媒体文件下载偶发失败：

```
[ERROR] sdk.finance_sdk: 下载媒体文件失败(内存), 错误码: 10001
[ERROR] insurance.handler: 保单处理失败, record_id=6303 filename=马阳阳驾意.pdf: 媒体文件下载失败或内容为空
```

`10001` 为企业微信 Finance SDK 的**网络错误**（`GetMediaData` 请求失败），属偶发抖动——同一队列紧接着的下一份 PDF 立即下载成功即可佐证。

**问题**：原 `_download_media` 没有任何重试，SDK 一返回非 0 即直接失败，记录被永久标记为 `failed`，需人工重传。一次网络抖动即导致一份保单丢失识别。

## 数据库变更

无。

## 代码变更

### `insurance/handler.py` — `_download_media()`

- 将单次下载逻辑抽成内部函数 `_try_once()`（兼容大文件临时文件 / 小文件内存两条路径，逻辑不变）。
- 外层增加**带退避的重试**：
  - 最多尝试 3 次，间隔 1s → 2s 递增。
  - 每次失败（非 0 错误码或异常）打 `warning` 日志，记录尝试次数。
  - 重试耗尽才走原失败逻辑：打 `error` 日志 + `notify_error` 告警 + 返回 `b""`。
- 对外接口签名与返回值不变（成功返 bytes，失败返 `b""`），上层调用与 SDK 接口均无需改动，**向后兼容**。

## 部署步骤

1. 拉取最新代码。
2. 重启服务：`python main.py`（无依赖变更、无 DB 迁移）。

## 影响范围

- 仅影响保单自动识别的媒体下载环节，下载更健壮。
- 偶发网络错误（10001 等）将自动重试，显著减少因瞬时抖动导致的 `failed` 记录。
- 持续性故障（如文件已过期、配置错误）仍会在重试耗尽后失败并告警，行为与原先一致。
