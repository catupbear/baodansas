# 修复申能"保险组合单"被误拆成多份、保费/保单号提取错误

## 需求说明

申能财产保险的「驾乘无忧+出行不便/420元5座保险组合单（个人）」(粤BB33720-非车.pdf) 出现两个问题：

1. **一份保单被识别成 3 条记录**：整单 + 2 个分项险种各成一条。
2. **保费完全提取不到**（显示「—」），且主记录保单号取成了分项号。

样例（PDF 第1页投保信息表，pdfplumber 实际抽取文本）：

```
保险组合单号：6203430000060260000569
...
险种名称：锦程交通意外伤害保险 分项保单号：6203430110160260001601
...
险种名称：个人出行不便损失补偿保险 分项保单号：6203430230760260000090
...
保险费总计： （大写） 肆佰贰拾元 小写 420.00元
```

该 PDF 是**一张组合单含多个分项险种**，正确结果应为 **1 条记录**，保单号取整单号 `6203430000060260000569`，保费 `420.00`。

## 根因

`insurance/policy_parser.py`：

1. **误拆分**：`_find_policy_boundaries` 的"兜底多保单检测"用 `保[险]?单号` 匹配保单号，把组合单里的两个**「分项保单号」**当成了独立保单号，从而拆成多条。分项保单号是同一整单下的子项险种编号，不应拆分。
2. **保单号取错**：`_extract_policy_no` 通用规则命中页面上第一个「分项保单号」，得到分项号而非整单号；组合单的「保险组合单号」未被识别（`保[险]?单号` 不匹配"组合单号"）。
3. 保费本身正则（`保险费总计…小写…元`）正确，但因记录被拆分、分项段内无该行，故取不到——根因仍是拆分。

## 代码变更

`insurance/policy_parser.py`：

- `_find_policy_boundaries`：兜底保单号检测中，跳过前缀为「分项」的「分项保单号」（组合单子项，不作为独立保单边界）。
- `_extract_policy_no`：
  - 新增最高优先级规则：存在「保险组合单号」时直接取整单号。
  - 「保单号：」通用兜底改为遍历跳过「分项保单号」，避免误取分项号。

## 验证

用真实 PDF（粤BB33720-非车.pdf）跑 `parse_policy_text_multi`：
- 保单条数：3 → **1**
- 保单号：6203430110160260001601(分项) → **6203430000060260000569**(整单)
- 保费合计：空 → **420.00**
- 投保人/被保险人/车牌/车架号/起止期等均正确，置信度 1.0

## 数据库变更

无。

## 部署步骤

1. 重启服务：`python main.py`
2. 对历史已被误拆成 3 条的该保单，删除旧记录后**重新识别**，即可合并为 1 条并补出保费。
