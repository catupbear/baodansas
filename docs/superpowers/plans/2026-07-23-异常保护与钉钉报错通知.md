# 异常保护与钉钉报错通知 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给台账系统（wxbot）补齐异常保护 + 钉钉报错通知，报错文案含完整 traceback 并标注"台账系统"。

**Architecture:** 三层防护——① `core/notify.py: notify_error()` 增强（自动采集 traceback，向后兼容全项目 15 处现有调用）；② API 层全局 Flask errorhandler（覆盖 web/api.py、insurance/api.py、callback/server.py 所有路由）；③ 后台常驻循环/定时脚本逐个补漏（只补缺失保护的地方，已达标的不改动）。

**Tech Stack:** Python 3 / Flask / pymysql，无测试框架（本项目无 pytest/lint/Makefile，验证方式为手动运行脚本片段 + 本地起服务 curl + 代码走查，不写自动化测试用例）。

## Global Constraints

- `notify_error(module, method, error, detail="")` 函数签名不能变，全项目 15 处现有调用点不能改动。
- 通知标题格式：`⚠ 台账系统 - {module} 异常`；正文首行含 `**系统**: 台账系统`。
- traceback 只在触发 `notify_error()` 时处于 `except` 块内（`sys.exc_info()[0] is not None`）才采集，最多保留最后 40 行。
- 不改变任何现有的局部 try/except 业务逻辑（OCR 兜底、SDK 重试等），只在"最终兜不住"的最外层补网。
- 不对 `insurance/policy_parser.py` 等内部字段提取函数做逐个包裹。
- `main.py` 新增的初始化/errorhandler 必须同步到 `run_ocr.py`（CLAUDE.md 强制要求）。
- API 响应格式统一 `jsonify({"code": xxx, "msg": "..."})`。

```python
def notify_error(module: str, method: str, error: str, detail: str = ""):
    """
    发送错误通知（异步，不阻塞业务流程）。

    Args:
        module: 模块名称，如 "消息拉取"、"保单识别"
        method: 方法/API 名称，如 "fetch_new_messages"、"/api/insurance/upload"
        error:  错误摘要
        detail: 补充信息（可选）
    """
    if not _notifier:
        return

    title = f"⚠ 台账系统 - {module} 异常"
    ts = time.strftime("%Y-%m-%d %H:%M:%S")
    lines = [
        f"### ⚠ 台账系统异常告警",
        f"- **系统**: 台账系统",
        f"- **时间**: {ts}",
        f"- **模块**: {module}",
        f"- **方法**: `{method}`",
        f"- **错误**: {error[:500]}",
    ]
    if detail:
        lines.append(f"- **详情**: {detail[:500]}")

    # 仅在 except 块内调用时才有堆栈；不在异常上下文时 sys.exc_info() 全为 None
    if sys.exc_info()[0] is not None:
        tb = traceback.format_exc()
        tb_lines = tb.strip().splitlines()
        if len(tb_lines) > 40:
            tb_lines = ["... (已截断，仅显示最后40行) ..."] + tb_lines[-40:]
        lines.append("")
        lines.append("**堆栈信息**:")
        lines.append("```")
        lines.append("\n".join(tb_lines))
        lines.append("```")

    content = "\n".join(lines)

    # 异步发送，不阻塞主流程
    threading.Thread(
        target=_notifier.send, args=(title, content), daemon=True
    ).start()
```

原文（`main.py:584-607`）：
```python
        def _stuck_processing_watchdog():
            import time
            while True:
                time.sleep(1800)
                lock_conn = db.pool.connection()
                got_lock = False
                try:
                    lock_cursor = lock_conn.cursor()
                    lock_cursor.execute("SELECT GET_LOCK('wxbot_stuck_processing_watchdog', 0)")
                    got_lock = lock_cursor.fetchone()[0] == 1
                    if not got_lock:
                        continue
                    try:
                        from insurance.api import recover_stuck_processing_records
                        recover_stuck_processing_records(timeout_minutes=10)
                    except Exception as e:
                        logger.warning("定时自愈扫描失败: %s", e)
                finally:
                    try:
                        if got_lock:
                            lock_cursor.execute("SELECT RELEASE_LOCK('wxbot_stuck_processing_watchdog')")
                    except Exception:
                        pass
                    lock_conn.close()

        threading.Thread(target=_stuck_processing_watchdog, daemon=True).start()
```

问题：`lock_conn = db.pool.connection()`（第588行）在 try 外部，`db.pool` 连接失败（DB 抖动/连接池耗尽）会直接抛出未捕获异常，杀死这个每 30 分钟跑一次的看门狗线程，且没有任何通知。

改为：
```python
        def _stuck_processing_watchdog():
            import time
            while True:
                time.sleep(1800)
                try:
                    lock_conn = db.pool.connection()
                except Exception as e:
                    logger.error("看门狗获取DB连接失败: %s", e, exc_info=True)
                    notify_error("卡死自愈看门狗", "_stuck_processing_watchdog", str(e))
                    continue
                got_lock = False
                try:
                    lock_cursor = lock_conn.cursor()
                    lock_cursor.execute("SELECT GET_LOCK('wxbot_stuck_processing_watchdog', 0)")
                    got_lock = lock_cursor.fetchone()[0] == 1
                    if not got_lock:
                        continue
                    try:
                        from insurance.api import recover_stuck_processing_records
                        recover_stuck_processing_records(timeout_minutes=10)
                    except Exception as e:
                        logger.warning("定时自愈扫描失败: %s", e)
                        notify_error("卡死自愈看门狗", "recover_stuck_processing_records", str(e))
                except Exception as e:
                    logger.error("看门狗执行异常: %s", e, exc_info=True)
                    notify_error("卡死自愈看门狗", "_stuck_processing_watchdog", str(e))
                finally:
                    try:
                        if got_lock:
                            lock_cursor.execute("SELECT RELEASE_LOCK('wxbot_stuck_processing_watchdog')")
                    except Exception:
                        pass
                    lock_conn.close()

        threading.Thread(target=_stuck_processing_watchdog, daemon=True).start()
```

注意：`continue` 语句在 `except` 分支里的作用域仍在 `while True` 内，语法上合法（Python 允许 try/except 内 continue 跳回外层循环）。
