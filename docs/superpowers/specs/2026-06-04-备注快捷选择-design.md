# 备注快捷选择（联动选择器）设计文档

- 日期：2026-06-04
- 状态：待评审
- 模块：保单识别 / 台账（insurance）

## 1. 需求说明

台账记录中有一个「备注」自定义字段，业务希望按记录的 **经办人 / 投保公司 / 险种** 自动筛出对应的「备注话术」供快捷点选，减少手动输入。

备注话术来源于一张外部 Excel 对照表，结构为：

| 日期 | 经办人 | 投保公司 | 备注信息 | 险种名称 |
|------|--------|----------|----------|----------|
| 6月4日 | 伦见富 | 东莞平安 | 非车500元及以上 | 驾意险 |
| … | 温霖 | 广东平安(地区) | 燃油私家过户车-70分内-0.85折-标件：… | 商业险 |

核心约束：

1. 该 Excel **每天重新生成**（甚至一天多次，按 sheet 区分时间点），需要**先清空旧选项池、再重新导入**。
2. 重导**不能影响历史记录里已经选过的备注值**——已选值存在记录自身字段中（计入 `manual_fields`），与选项池是两套独立存储，清空选项池不触碰任何记录。
3. 形态是一个**「备注选择器弹窗」**：打开时已按本行的经办人/投保公司/险种自动筛好候选，可再调整匹配方式、搜索、选取。

## 2. 关键决策（已与用户确认）

| 决策点 | 结论 |
|--------|------|
| 三个匹配键来源 | **设置里手动指定** 经办人/投保公司/险种 各自对应的记录字段 key（最灵活，不写死） |
| 公司名匹配方式 | 弹窗内支持 **精准 / 模糊** 切换，**默认精准**（空键不参与过滤） |
| 上传与作用范围 | **设置页上传**，按 **企业 / 个人 scope**（复用现有 `insurance_config` scope 机制） |
| 匹配兜底 | 形态为**弹窗**：弹窗已自动按那几个字段筛选，匹配不到时列表为空但用户可放宽键/搜索/自由保存 |
| 多 sheet 导入 | 上传后**弹窗列出所有 sheet，默认勾选最后一个（最新时间点）**，可改 |
| 选择器入口 | 台账列表中**备注单元格加「选择」图标**，点击打开弹窗 |

## 3. 存储方案

### 3.1 选项池表（新建）`insurance_remark_options`

| 列 | 类型 | 说明 |
|----|------|------|
| id | BIGINT PK AI | |
| scope | VARCHAR(16) | global / enterprise / user，复用现有 scope 语义 |
| scope_id | VARCHAR(64) NULL | 企业 parent_id 或 user_id |
| handler | VARCHAR(64) | 经办人 |
| company | VARCHAR(128) | 投保公司 |
| policy_type | VARCHAR(64) | 险种名称（可空，部分 sheet 无此列） |
| remark | TEXT | 备注信息 |
| batch_no | VARCHAR(32) | 本次导入批次标识（导入时间戳），便于排查 |
| created_at | DATETIME | |

索引：`(scope, scope_id, handler, company, policy_type)` 联合索引（精准匹配走索引）。

> 表在首次启动时自动创建（沿用 `insurance/db.py` 现有「启动自动建表/补列」模式）。

### 3.2 配置（存 `insurance_config`）

`config_type = 'remark_selector'`，按企业/个人 scope，内容：

```json
{
  "enabled": true,
  "target_key": "备注",        // 备注目标字段（哪一列出现「选择」图标）
  "key_handler": "经办人",      // 经办人对应记录字段
  "key_company": "承保公司",    // 投保公司对应记录字段
  "key_policy_type": "险种"     // 险种对应记录字段
}
```

> 三个 key 与 target_key 均从「当前列配置字段列表」中下拉选择，避免写死字段名。

## 4. 数据流

```
设置页上传 Excel（按企业/个人 scope）
  → 后端 openpyxl 读取，按表头(经办人/投保公司/备注信息/险种名称)定位列（非按列号，容忍尾部多余空列）
  → 列出所有 sheet，前端默认选最后一个；选定 sheet 提交导入
  → 同 scope 旧行 DELETE → 新行去重(handler+company+policy_type+remark)后批量 INSERT，记 batch_no
  → 记录里的备注值完全不动

台账记录行 · 备注单元格点「选择」图标
  → 打开「备注选择器弹窗」
  → 按设置 key_* 从本行取 经办人/投保公司/险种 作为筛选条件
  → GET 候选备注（默认精准；可切模糊 + 备注关键词搜索）
  → 点选一条 → 复用 saveListEdit → PUT /fields → 写入备注字段并计入 manual_fields（持久，不被重识别覆盖）
```

## 5. 后端接口

复用 `insurance_bp`，统一 `/api/insurance/remark-options/*`：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/insurance/remark-options/sheets` | 上传 Excel，返回 sheet 名列表（不落库，供前端选 sheet） |
| POST | `/api/insurance/remark-options/import` | 提交导入：上传文件 + 选定 sheet → 清空当前 scope 旧池 + 导入新池，返回导入条数 |
| GET | `/api/insurance/remark-options/query` | 入参 handler/company/policy_type/keyword/mode(exact\|fuzzy)，返回候选 remark 列表 |
| GET | `/api/insurance/remark-options/stats` | 返回当前 scope 选项池条数 + 最后导入时间(batch_no) |
| DELETE | `/api/insurance/remark-options` | 清空当前 scope 选项池 |
| GET/PUT | `/api/insurance/config`（扩展） | 读写 `remark_selector` 配置块 |

匹配逻辑（query）：
- **exact（默认）**：handler/company/policy_type 三键非空者精确等值过滤；keyword 仍按子串过滤备注。
- **fuzzy**：三键改为子串包含匹配；keyword 同样子串过滤。
- 任一键为空 → 该键不参与过滤（放宽）。

## 6. 前端改动（`web/templates/insurance.html`）

1. **备注单元格**：当列 key == `remark_selector.target_key` 且功能 enabled 时，单元格内追加一个「选择」图标按钮，点击 `openRemarkSelector(record)`。
2. **选择器弹窗组件**：
   - 顶部显示并允许临时取消三个筛选键（经办人/投保公司/险种）；精准/模糊切换开关（默认精准）；备注关键词搜索框。
   - 列表展示候选 remark，点选 → 复用现有 `saveListEdit` 路径写回（确保进 manual_fields）。
   - 空结果时提示「未匹配到，可放宽筛选或直接手动填写」。
3. **设置页新增「备注快捷选择」区块**：
   - 开关；target_key / key_handler / key_company / key_policy_type 四个字段下拉（取自当前列配置字段）。
   - Excel 上传入口（先 `/sheets` 取 sheet → 选 sheet → `/import`）。
   - 展示「当前选项池：N 条，最后导入：xxx」+「清空」按钮。

## 8. 兼容性

- 纯新增功能：未开启 `remark_selector.enabled` 时，台账与现有行为完全不变。
- 选项池与记录字段解耦：清空/重导选项池永不修改任何记录，满足「不影响历史已选」。
- `target_key` 不存在或未配置时，不显示选择图标，不影响其它单元格编辑。

## 9. 不做（YAGNI）

- 不做选项池的版本历史/回滚（只保留最近一次导入，batch_no 仅用于排查）。
- 不做自动定时拉取 Excel（仍由人工每日上传）。
- 不改动 OCR / 钉钉同步链路。
