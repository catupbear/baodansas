# 群内补充信息「待匹配池」设计方案

> 2026-07-19 · 已与需求方确认

## 背景与问题

客户在群里发补充信息（车牌 + 业务经理/业务专员/保险公司经办人等）时，同车牌保单
可能还在识别队列中（PDF 识别较慢），系统按车牌命中 0 条记录就**立即**发「⚠️ 补充信息未录入」
群提醒，造成误报——客户明明刚发了保单，只是还没识别完。

## 需求（已确认）

1. 命中 0 条时不立即提醒，**延迟 10 分钟**后仍未匹配才发「未录入」提醒
2. 未匹配的补充信息进入**待匹配池**，保单识别成功后自动匹配回填并移除
3. 匹配成功通知：仅在已发过「未录入」提醒后才补发「已自动录入」通知（10 分钟内静默匹配不打扰）
4. 池子条目 48 小时未匹配自动过期作废（避免车牌填错的脏数据长期滞留误匹配）

## 方案

### 存储：MySQL 表 `policy_fill_pending`（首次启动自动建表）

线上 gunicorn 带 `--reload`，内存池会因进程重启丢失，故落库持久化。

| 字段 | 说明 |
|------|------|
| roomid / room_name | 群 id / 群名（入池时用 fetcher 所属企业通讯录解析好，延迟通知不再依赖 fetcher 上下文） |
| sender / sender_name | 发送人 id / 解析后的名称（@用，解析失败存空=不@） |
| enterprise_id | 群所属企业 |
| plate | 归一化车牌（去 -/空格/间隔点，大写） |
| fill_fields | 解析出的补充字段 JSON |
| raw_text | 原始补充文本 |
| status | pending → notified → matched / expired |
| notify_at / expire_at | 提醒时间点（+10min）/ 过期时间点（+48h），均用 DB NOW() 计算 |
| matched_record_id / matched_at | 匹配到的记录与时间 |

索引：`(roomid, plate, status)`、`(status, notify_at)`

### 流程改动

1. **入池**（`core/fetcher.py` `_check_policy_fill_trigger` 命中 0 条分支）
   不再立即调 `_notify_policy_fill_miss`，改为解析群名/发送人名后写入池。
   同一群+同车牌+同发送人的未决条目 → 合并字段更新（不重复入池、不重复提醒）。

2. **识别成功自动匹配**（`insurance/handler.py`）
   `_process` 在跨保单互补/TZ-008 兜底之后、字段映射之前调用 `match_and_apply`：
   按 roomid+归一化车牌查池中 pending/notified 条目，把 fill 写入本条 `parsed_fields`
   （在首次钉钉同步前生效）。条目标记 matched；若此前已发「未录入」提醒（notified），
   补发「✅ 补录成功」群通知。`_copy_recognition_result`（同 md5 秒传路径）同样调用。
   **多保单 PDF 兼容**：matched 后 10 分钟宽限期内，同车牌新记录仍可复用该条目的
   fill（交强+商业两条记录都要回填），但通知只发一次（靠状态抢占保证）。

3. **延迟提醒线程**（`insurance/fill_pending.py`，main.py 启动，全局一个）
   每 30 秒扫表：
   - `expire_at <= NOW()` 的未决条目 → 置 expired
   - `status=pending AND notify_at <= NOW()` 且通知开关开启 → 逐条用
     `UPDATE ... WHERE id=%s AND status='pending'` 抢占（多 worker 安全），
     抢到的发 FlowBot「未录入」提醒（沿用现有文案模板与 @ 逻辑），
     **同时推一条钉钉通知**（复用系统告警机器人，含群/发送人/车牌/补充内容，
     模式同 `notify_unmonitored_group`，便于技术客服跟进）
   - 通知开关关闭时条目留 pending，只做匹配不提醒（匹配回填不受开关影响）

### 配置（沿用 `insurance_config` 表 `quote_fill_miss_notify` 键，无前端改动）

| 键 | 说明 |
|----|------|
| enabled / robot_id / tech_support_name / template | 沿用现有 |
| delay_minutes | 新增，延迟提醒分钟数，默认 10 |
| pool_expire_hours | 新增，池子有效期小时数，默认 48 |
| template_matched | 新增，补录成功文案（{plate} 占位），有默认值 |

### 异常兜底

所有池操作旁路化：异常只记日志，绝不影响消息拉取与保单识别主流程（与现有通知逻辑一致）。

## 改动文件

- 新增 `insurance/fill_pending.py` — 建表、入池、匹配回填、扫描线程、两类通知
- `core/notify.py` — 新增「未录入」钉钉通知函数（复用系统告警机器人）
- `core/fetcher.py` — 命中 0 条分支改入池；删除立即提醒函数（模板迁至 fill_pending）
- `insurance/handler.py` — `_process` 与 `_copy_recognition_result` 增加池匹配调用
- `main.py` — 初始化建表并启动扫描线程
