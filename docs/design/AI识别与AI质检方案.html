一、背景与目标

现状：识别流水线为「pdfplumber 文本提取（失败降级 百度/火山 OCR）→ policy_parser 正则规则解析（50+ 保司）」。规则解析对新保司、新版式、扫描件容易出错或漏提，目前只能靠人工在前端逐字段修改。

目标：

功能说明触发方式可见范围
AI质检（手动兜底）识别出错时，内部人员在操作列点「AI质检」，用多模态大模型直接读 PDF 原件提取字段，对比后勾选覆盖手动仅超管（内部）
AI质检（自动）按客户（企业）配置开启：该企业每份保单识别完成后，自动用大模型复核提取结果；发现差异按策略自动修正，并发钉钉机器人通知内部自动后台运行，超管可看质检记录

设计原则：大模型只做「兜底 + 质检」，不替换现有规则解析主链路（成本可控、行为可回溯）；模型厂商/模型名/密钥全部走配置，随时可切换。

要点：

  • 所有国产主流多模态模型均兼容 OpenAI Chat Completions 协议，只需实现一套客户端，通过 base_url + model + api_key 切换厂商，不引入各家专属 SDK。
  • Prompt 固定输出 JSON（字段清单来自 policy_parser.FIELD_ORDER），带「未识别到填 null，禁止编造」约束；prompt 模板存配置，可在线调整。
  • 优先发送 PDF 页面图片（对扫描件、盖章、表格版式最稳）；若 PDF 文本层质量好（raw_text 长度达标），可配置为「图片+文本」双通道输入以提高准确率。
  • 渲染用 pypdfium2（pdfplumber 新版本身依赖它，无额外系统依赖），图片压缩到长边 ≤1600px 控制 token。

三、功能一：内部操作列「AI质检」（手动）

3.1 交互流程

  1. 超管在记录列表操作列（或预览弹窗工具条）点 AI质检；
  2. 后端同步调大模型（预计 5~20 秒，前端按钮转圈），返回 ai_fields；
  3. 弹出「AI识别对比」弹窗：三列对比（字段 / 当前列表值 / AI提取值），差异红色高亮，手动改过的字段带橙点标记（交互复用现有「识别对比」面板 + 「勾选覆盖」弹窗的模式）；
  4. 勾选要采纳的字段 → 点「应用勾选的AI值」→ 后端写入 parsed_fields / display_fields，被覆盖字段记入 ai_fields 标记（类比 manual_fields），原值备份进 ai_corrections；
  5. 不自动同步钉钉多维表：应用 AI 值只改系统内数据；如需更新台账，人工确认后走现有手动同步入口。
AI 结果永不自动落库（功能一里），必须人工勾选确认——内部兜底工具，人是最后一道关。
每次操作必留痕：只要点了「AI质检」，无论最后是否勾选覆盖，都在 ai_check_log 写一条流水（trigger_type=manual）：操作人、记录ID、模型、耗时、token 消耗、差异数、结果状态——未应用为 extracted，应用后更新为 applied 并记录实际覆盖的字段与原值备份。调用失败也记 error。全部流水可在「质检流水」页按操作人/日期筛选（超管）。

「AI直接覆盖」双层开关设计：① 全局总开关（AI模型设置页，默认关）——关闭时所有企业强制「仅标记」，一键熔断；② 企业级开关（客户管理页）——总开关开启后，按企业逐个放开直接覆盖。两层都开才会真正自动改数据。

4.2 质检范围条件 + 比对与修正规则

规则说明
质检范围条件每个企业可选「全部」或「自定义条件」，自定义为多条件或关系（命中任一即质检），不使用置信度：
① 按状态多选：非保单 / 需人工补充 / 识别异常 / 识别失败 / 正常完成（如勾「非保单」= 用 AI 复核是否被规则误判为非保单；勾「需人工补充」= 用 AI 尝试补齐缺失字段）；
② 按保司多选：只质检勾选的保险公司；
③ 按保司成熟度：该保司历史总识别数 < xx 单的（新保司/小众保司规则不成熟，自动重点质检，随识别量增长自动退出范围）。
比对范围默认核心字段集（保单号、车牌、车架号、被保险人、保费、起/止保日期、保司、险种），可在配置中勾选增减；金额/日期先归一化（去千分位、统一日期格式）再比。
跳过字段manual_fields 中人工改过的字段永不自动修正（只提示差异）；公式计算字段、群内补充字段跳过。
修正条件仅当「列表值为空 AI 有值（补充）」或「AI 值与原文可交叉验证」时自动改；AI 也拿不准（返回 null / 与规则值互相矛盾且无法验证）→ 只标记待确认，不改。
可回溯每次修正把 {字段: {原值, AI值, 时间}} 追加进 ai_corrections，前端质检详情可查、可一键还原。
频控同一记录只自动质检一次（重识别后重置）。不设质检额度上限，全量质检；成本通过企业统计看板（原型 G）与日成本提醒监控。

6.2 新表 ai_check_log（质检/调用流水，成本统计用）

CREATE TABLE IF NOT EXISTS ai_check_log (
  id INT AUTO_INCREMENT PRIMARY KEY,
  record_id INT NOT NULL,
  enterprise_id INT DEFAULT NULL,
  trigger_type VARCHAR(16) COMMENT 'manual(功能一)/auto(功能二)',
  operator_user_id INT DEFAULT NULL COMMENT '操作人（manual 必填，auto 为空）',
  operator_name VARCHAR(64) DEFAULT NULL COMMENT '操作人姓名快照',
  model VARCHAR(64),
  result VARCHAR(16) COMMENT 'extracted(已识别未应用)/applied(已应用)/pass/corrected/flagged/error',
  diff_json LONGTEXT COMMENT '差异明细',
  applied_fields LONGTEXT COMMENT '实际应用覆盖的字段及原值备份JSON（未应用为空）',
  prompt_tokens INT, completion_tokens INT,
  duration_ms INT, error_message TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_record (record_id), INDEX idx_ent_time (enterprise_id, created_at)
);

6.3 insurance_config 新增 KV

config_key内容
ai_model_config{enabled, allow_auto_fix（全局「允许AI直接覆盖」总闸，默认 false）, models: [{id, name, provider, base_url, model, api_key, timeout, enabled, priority}]（多模型列表）, active_model_id（当前使用）, max_pages, cost_alert_threshold（日成本提醒阈值，仅提醒不拦截）, notify_webhook + notify_secret（钉钉通知机器人，留空回退现有告警机器人）, prompt_template}
ai_check_enterprises{enterprise_id: {enabled, scope: {mode: all/custom, statuses:[非保单, 需人工补充, 识别异常, 识别失败, 正常完成], companies:[…], company_history_lt: 50}（自定义条件为或关系）, auto_fix: true/false（企业级「AI直接覆盖」开关，默认 false）, compare_fields:[…]}}
实际是否直接覆盖 = 全局 allow_auto_fix 且 企业 auto_fix 同时为 true；不设质检额度限制；不使用置信度

九、成本估算与风控

项估算/措施
单次调用成本4 页图片 ≈ 3k~6k 输入 token + ~0.5k 输出；qwen-vl-max 约 ¥0.02~0.06/单，qwen-vl-plus / doubao-vision 约低一个档（以官网现价为准，试跑后校准）
日成本示例某企业日均 40 单全量质检 ≈ ¥1~3/天/企业。不设质检额度上限（全量质检），成本靠企业统计看板（原型 G）+ 日成本提醒阈值（超过发钉钉提醒，不拦截）监控
数据安全保单含个人信息，发往大模型 API 前不脱敏（提取需要原文）；仅走官方 API、不开训练授权；API Key 打码回显；建议在客户协议中覆盖
幻觉防控Prompt 强约束「未识别填 null 禁止编造」；自动修正仅限可交叉验证场景（4.2）；人工改过的字段永不自动改；全部修正可还原
失败降级当前模型超时/报错 → 按优先级自动切换下一个「启用」的模型（实际使用的模型记入流水）→ 全部失败记 error 不影响主流程；质检线程异常自动重启（复用 handler 守护线程模式）

十、需求确认记录（Q1/Q3~Q6 已确认，Q2 为建议项）

Q1. 差异处理策略 —— 已确认：做成「AI直接覆盖」双层开关
全局总闸（AI模型设置页）+ 企业级开关（客户管理页），两层都开才直接覆盖，否则仅标记+通知。两个开关默认均为关闭，建议先「仅标记」跑两周验证准确率后再按企业放开。
Q2. 首批配置哪几个模型？（已按多模型列表设计，可随时增删切换）
建议：优先级1 qwen-vl-max（当前使用，准确率优先）+ 优先级2 doubao-seed-1.6-vision（备用，便宜且已有火山账号），上线后按统计看板的实际表现调整。
Q3. 「AI识别」按钮开放范围 —— 已确认：仅内部超管，不开放给企业客户
AI质检按钮、质检徽标/问题列表、模型配置、企业质检开关全部仅超管可见可操作。
Q4. 钉钉多维表同步 —— 已确认：一律不自动同步
AI 识别/质检产生的任何修改都不推送钉钉多维表；有问题的记录统一进系统内「AI质检问题列表」（原型 F）处理，需要更新台账时人工走现有同步入口。
Q5. 历史存量保单补跑质检 —— 已确认：暂不考虑
只质检新入库记录，不做历史补跑（后续有需要再排期）。
Q6. 钉钉通知 —— 已确认：webhook 后台可配置
在「AI 模型」设置页配置通知机器人 webhook + 加签密钥，支持发送测试消息；留空则回退复用现有系统告警机器人（core/notify.py）。
